# Slim down

Part of the `remove-a-stopgap` skill. Until Nov 17, 2026 this was the `slim-down` skill; the CTO merged it here when the skills were capped (owner: "Let's go ahead"). What it covered: Removes duplicate and dead code with no behavior change: what to check before deleting a file or merging copies, the traps already hit (import cycles from a replaced module name, validated versus plain helpers), and what each PR proves. Use for any consolidation, dead-file, one-lookup or one-kit PR. Not for changes that alter what the game does, which belong to the owning session.

Structure only, no behavior change, small PRs. A change that alters behavior is a seam for the CTO and the owning session, not yours. Take only items at the pool item standard (`docs/pool/START-A-BUILDER.md`).

- **Dead file**: grep the whole repo (`src`, `scripts`, `tests`, CSS class names) for the file name and its exports before deleting. Docs that only mention it are fine to leave. Delete the CSS that styled it in the same PR.
- **A dead script is more than a name search (Nov 15, scripts/words).** Before deleting a script in `scripts/`, search `package.json`, `tests`, `docs/pool/items` (an open item's `Files:` line and its measuring command count as callers: `npm run pool -- --check` fails when a named file is gone, so a script an open item measures with stays), and comments in `src` and `data` that say "written by scripts/..."; fix each pointer in the same PR. Then run it once on a clean tree and restore the data with `git checkout`: a script that crashes, or rewrites a bank (the speech-bank script would have rewritten opening-speech.json by about 56,000 lines), is dead by the owner's rule (Nov 15: "If there's old shit... Delete it"). Do not add the path to `docs/current.json`'s `replaced` list: that list is going away and git holds the history. Ask each lane that might run a proof by hand once, and delete every one nobody claims.
- **Copies of a helper**: diff the bodies first. Copies that look the same can differ on an edge (`ageOnDate` validates dates and moves a Feb 29 birthday to Feb 28; the hand-written copies compare text). Point copies at a shared function with the exact same formula, never at a "nearby" one. A validated helper in a hot loop also makes the year slower.
- **Hand-typed module id -> the module's constant**: only safe in leaf code (`src/bench`, tools). In `src/core2` files that sit inside the module import cycle (candidate-pool, shared-history, heard-claims, jobs-elsewhere) the import is `undefined` or in its temporal dead zone when the call runs, and tests die with "Cannot access ... before initialization" or "Module keys must be nonempty". The typed name is deliberate there; leave it, or move the constant to a leaf file such as `business-module-id.ts`.
- **A deleted fix is a fix**: if swapping a name reveals a real bug (dev-why read "budgets", the module is "core2-budgets-v1"), say so in the PR body.
- **Proof** (builders build, checkers check; owner, Oct 29): run prettier and eslint on the files you changed and the tests that import them, one at a time. The checker runs typecheck (`npx tsc -p tsconfig.node.json --noEmit`) and the gate. A typed-name swap that fails only at run time (the cycle trap above) is why the importing tests matter. A main-red prettier file is not yours.
- **PR body**: line 1 `Pool item: <id>` (`Pool item: none` when no item covers it), line 2 `Session: Slim down`, then lines removed, and a release declaration `impact: none`.
- **A duplicate variant is a duplicate only if its lines play from another place** (#9394, Nov 15). Before deleting a variant or arc as "the same as plain", search the bank for each line the deletion removes, in the head you will gate. If a line exists nowhere else, the variant was the only place it played: move its uses to the shared set (`set: case-help`, keep `requiresFacts`) instead of deleting it, then replay the cases at that head. A played file made before the deletion proves nothing about the deletion. A staged record uses the record's real kind: the layoff row staged for a job seeker points at an organization of kind employer (not an account or a treasury), or the played file shows a line no real world can say; and a fact that names a record (the employer) is set only when the record is of the kind the line says (constituent-help-facts.ts sets employer only for an employer). A fact the lines need (a job seeker's `employer` and `since`) may be on the books in only a few drawn places; stage it through the game's own path (a layoff row on the case's asker) and say so in the file, since drawn places alone will not show it.
- **Name the kind first (Nov 26).** A _duplicate_ is two pieces doing one job: merge them and delete one. A _bypass_ is a single source that exists while callers go around it: point the callers at it. A _gap_ is something missing; that is new work, not slimming, and doesn't go in a slimming PR. The game-wide list is the CTO's refactoring map of Nov 26, linked on the crew thread (#10377); check it before building anything new.
- **Before the start, day one and play (Nov 26).** The pre-start run steps each engine's own records at a coarser pace by design (`pre-start.ts`), so a separate loop for the past is not a duplicate. Ask whether it runs play's own rule. A separate model of the same thing is the duplicate (`past-health.ts`'s own rate; the century's own law sessions). Making who exists on day one (relatives, partners, households) is generation, and it stays.
- **Ports of the old engine (Nov 26).** The old engine's folders are gone, but a file whose header says it was ported from the old engine still runs that engine's rule for something a live engine now does (`opening-town-jobs.ts`, `opening-upbringing.ts`). Find them by reading headers, not only folder names.
- **Two files that each call themselves "the one" X are a duplicate to settle (Nov 26).** Examples: `outline-planner.ts` and `speech-outline.ts` (the one outline planner), and `person-life.ts` and `past-history.ts` (the one list or reader every screen reads). Read both before naming which one stays.
- **A bypass's key may not be the reader's key (Nov 26, History).** Before pointing a lookup at `historyOf` or `historyEvent`, check the reader's id for the record is the key the lookup searched by. `lawHistory` finds a law's past by its `lawId` index, while the reader's row is `law-history:<the smallest row id of the law's group>`; reading it by `law-history:<this law's id>` would miss every other law in the group. Prove the move by comparing the old and new answers for every record in a world, then the records proof.
- **Typecheck before the before-and-after run (Nov 27, History, map row 4).** tsx runs code without its types, so a read of a field the new type lacks (`entry.kind` on a history reader event, whose kind is `record`) is undefined at run time and quietly false; a comparison started first ran that code and was thrown away. Capture what you compare (here the Journal's moment list) with a one-line `globalThis` hook in both checkouts, compare it deep-equal with the screens' output, and delete the hook by searching for it before you commit: prettier rewraps the line.
