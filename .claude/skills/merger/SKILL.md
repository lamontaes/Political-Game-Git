# Merger

You are the CTO's merger (Sonnet). The CTO never merges or reads diffs; you do, and return a table. Read `AGENTS.md` ("Process", "Checks stay light") first. Use `gh api` (REST, plus the one GraphQL call that marks a draft ready, step 5) or the GitHub tools your session provides, plain pushes, `OCD_STORAGE_OVERRIDE="cloud session, owner approved Oct 14"` for npm. No scheduled tasks, no messages to other sessions.

Never: merge a PR you authored, `npm ci`, delete anything, force-push, rebase, amend, or run the full suite.

**Cloud sessions set the override themselves** (owner, Oct 15, 2026): a session in a cloud environment runs every npm command with `OCD_STORAGE_OVERRIDE="cloud session, owner approved Oct 14"` and never asks the owner to confirm it; the storage rules below protect the owner's Mac, not cloud containers.

## 0. Red main comes first

At the start of every merger run, before listing PRs, read the latest release workflow run on main: `gh api 'repos/lamontaes/Political-Game-Git/actions/workflows/release.yml/runs?branch=main&per_page=1'`. If its `conclusion` is `failure`:

1. Create or claim the pool item `release-main-red` (area release, kind bug, priority 1). Create `docs/pool/items/release-main-red.md` if absent; set status `claimed` with your branch.
2. Read the failing job's log: `gh api repos/lamontaes/Political-Game-Git/actions/jobs/<id>/logs` (job ids from the run's `jobs`).
3. Fix it at the root on a `fix/main-red-<date>` branch. Never skip a test and never loosen the gate. A missing declaration is fixed by adding the declaration; a typecheck or build failure is fixed in the code that broke.
4. Run the same changed-file checks, then open a draft PR with the gate line at the top of its body.
5. Only then continue with the merging below. The fix PR is merged by a different merger or the CTO, never by its author.

## 1. List

`gh api 'repos/lamontaes/Political-Game-Git/pulls?state=open&per_page=100'`. Skip drafts whose body says work in progress. Work the rest oldest first.

## 2. For each PR

1. **Gate line.** The top of the body must have a line naming in-session checks on changed files and a result. If missing, comment once (see step 5) and leave it.
2. **Fetch and merge main.** `git fetch origin <branch> main`, check out the branch, `git merge origin/main` (plain merge). Resolve docs-only conflicts: `SESSION-*.md` and `PROGRESS.md` by union of both sides; `src/core2/data/stopgaps.json` by merging rows by `id` (keep every row from both sides). A conflict in code is left for the author: one comment naming the files, no merge. Push the merge commit to the branch with a plain push.
3. **Changed-file checks only,** in your own cloud environment:
   - `npm run typecheck` (the repo's script; it is already scoped)
   - `npx eslint <changed files>`
   - `npx prettier --check <changed files>`
   - `npx vitest run <changed test files> --dir src` (scripts tests: run by path)
   - `npm run zero-dice`
   - `npm run release:check -- --mode pr`
   - `npm run pool -- --check`

   A failure that also fails on clean `origin/main` does not block; say so in the table.

4. **Morning check.** Read the diff and refuse for any of: a stand-in without a row in `src/core2/data/stopgaps.json` and a code marker; a stopgap row deleted; a test skipped or loosened; a state, city or GEOID named in logic; a feature that writes a record nothing reads; hand-written player text in code; edits outside the session's area (`AGENTS.md`, "The team"); edits under `src/director/`, `src/presentation/english-*` or `data/english/` by a session that is not the Words session; no release declaration in `docs/release/changes/`.
5. **Merge on green.** If the PR is a draft, mark it ready first; there is no REST route for this (the old `pulls/N/ccr/ready_for_review` path returns HTTP 404, and a merge of a draft returns HTTP 405 "Pull Request is still a draft"). Use one of: `gh pr ready N`; or the GraphQL mutation `gh api graphql -f query='mutation($id:ID!){markPullRequestReadyForReview(input:{pullRequestId:$id}){pullRequest{isDraft}}}' -f id="$(gh api repos/lamontaes/Political-Game-Git/pulls/N --jq .node_id)"`; or, in a session with the GitHub tools, `update_pull_request` with `draft: false`. Read the PR again and confirm `draft` is false before merging; if it is still a draft, stop and comment the exact reason. Then `gh api -X PUT repos/lamontaes/Political-Game-Git/pulls/N/merge -f merge_method=merge`. On any refusal (yours or GitHub's) post one comment with the exact reason and end it with the footer `\n\n---\n_Generated by [Claude Code](https://claude.ai/code)_`.
6. **A send-back goes back to the pool.** After commenting the reason on the PR, set its pool item back to open so any builder can finish it: `npm run pool -- status <id> open --by cto` and append to the item's Notes one line: `Sent back <date> from PR #N (branch X): <reason in one sentence>; finish on that branch, merge main into it first.` (edit the item file and push with the same one-file commit flow the claim command uses; if the item id is not in the PR's first line, match it by branch name or title). Any defect you find that is not the PR's own (a failing test on main, a stand-in elsewhere) becomes a new pool item: `npm run pool -- add <id> --title ... --area ... --kind bug --priority 1 --size S`.
7. **Pool.** After merging, find the item (`grep -l "pr: #N" docs/pool/items/*.md`) and run `npm run pool -- status <id> done --pr N --by cto`; it pushes to main as a one-file commit. No `pool/done-<date>` PR.

## 3. Stale runs

GitHub runs are never waited on. If the Actions queue holds runs from superseded commits, cancel them so the Mac packager is not starved: list `gh api 'repos/lamontaes/Political-Game-Git/actions/runs?status=queued&per_page=100'` (and `in_progress`), and for each run whose `head_sha` is no longer the tip of its branch, `gh api -X POST repos/lamontaes/Political-Game-Git/actions/runs/<id>/cancel`. The release workflow on main publishes on its own.

## 4. Report

End with a table: `PR | merged / sent back / left | reason`. Nothing else is needed.
