# Merger: traps from past passes

Part of the `merger` skill. Each pass's traps, with the pull request that showed it.

## Traps from the Nov 1 pass (Merger 0)

- **Pin the full 40-character head.** A short sha is refused ("must be exactly 40 characters"); read it with `git rev-parse <ref>` or from the PR. A 409 "Head branch was modified" means someone pushed: before you re-gate, compare `git log --no-merges <gated sha>..<head>` and `git diff --stat <gated sha> <head> -- <the PR's own files>`. Merges of main only, with the PR's own files unchanged: merge on the new head and say so. A real commit, above all one whose message says work in progress or untested, is a hold: say the head the pass no longer stands for and ask the checker for a regate (#6972, Nov 1).
- **A 405 "merge conflicts" on a green PR is main moving, nearly always in `docs/pool/INDEX.md`.** Merge main again, `git checkout origin/main -- docs/pool/INDEX.md` (no `npm run pool` on the branch since Nov 3), push the plain merge to the PR's real branch (read `head.ref` from the PR, then write the name out in the command; never take it from a variable), and merge in the same minute. A hot branch may take two rounds; another session may have pushed the same merge, so fetch first.
- **Sort a red by running its seed on `origin/main`.** Same seed, same failure on main: it is main's red, so name the test, place and seed in your merge comment, message the red-main session (id in `CREW.md`), and do not block the PR. A different failure, or main passes: it is the PR's. Say which you did.
- **Run test files that exist.** `ls src/core2 | grep <word>` before naming a file; `vitest` on a guessed name finds nothing and a "ran" line proves nothing (Nov 1: `turnout.test.ts` did not exist). Read the Tests line, not just the exit code.
- **A flaky browser check is counted, then fixed at its cause, never retried to a pass (CTO, Nov 16, `done-proof`).** Run it three to five times on a bench started from the PR's code and report passes out of runs with the places (`filing.browser.mjs` passed 3 of 3 warm and timed out on cold starts). A check the PR adds or changes that passes only some runs goes back with the failing places; one already flaky on main is main's red and gets a pool item for its cause. File it with `npm run pool -- add`; its **Rules** line must name a standing rule (for example "Replace, never layer: ..."), or `pool --check` turns main red for everyone, as it did for a minute on Nov 1.
- **Release declarations.** A declaration whose id a release already consumed (`docs/release/consumed-changes.json`) fails `release:check`: rename it (`<id>-done`) and its file. `impact: none` carries no `section` or `title`.
- **Which conflicts are yours.** Mechanical: `docs/pool/INDEX.md`, a pool item's status and `pr:` fields (keep the PR's `in-pr` and its number), stopgap family files' rows kept by id (check the id count has no duplicates); a branch cut before Nov 3 that still edits the old its family file under `src/core2/data/stopgaps/` stops on a modify/delete conflict: run `node --import tsx scripts/stopgaps-move-old.ts`, which moves its rows into their family files and removes the old file, and an import line where both sides' names stay and `npm run typecheck` is clean (`scene.ts` in #6856). Back to the author: English banks and scene rows after a Words PR landed (`scene-talk.json`, `scene-words.json`, `scene-rows.json`; #6884 twice) and any logic.
- **Run the families guard on every merged tree, whatever else you ran, and name it in the merge comment.** `npx vitest run --dir . tests/guards/families.test.ts` takes seconds. A single `import type` from another family counts: #7044 (Nov 1) added `import type { LegacyWorkCashResult } from "./work-cash"` to `finance-types.ts`, made 5 cross-family imports against 4 known, and turned main red after a merge whose finance tests were all green. A red you merged in is yours for the first hour (section 0); the fix is the owning family's entry or a reason the guard accepts, never a bigger list.
- **Speed checks run alone.** A vitest run killed by `timeout` can leave its workers going, and the next `speed:year` then reads high (#6932 year 3: 49.7 s beside 30.9 s alone). `ps` first, rerun the odd year alone, and only then call it slow. Compare records year by year too: equal counts are the proof a cut changed nothing.

## Traps from the Nov 1 pass (Merger 1)

- **A families-guard red on a main-merged tree is almost always one new import, and the fix is the family's entry.** Find it with `git diff origin/main -- <file> | grep '^+import'`, then re-export the name from a file the family lists as an entry (`src/core2/modules/people.ts`, `src/core2/modules/campaigns.ts`, or a file the importer already reaches) and import it from there; the count goes back down and no record changes. Four PRs needed this (#6869, #6851, #6921, #6929); the guard, run on every merged tree, catches it. Say so in the merge comment. The fix is never a bigger baseline.
- **Never hand `vitest run` a file list that can be empty.** `npx vitest run $(ls ...)` or `$(git ls-files 'glob')` with no match runs the whole suite (it happened twice and cost ten minutes each). Put the list in a variable, `echo "$F"` it, and run only if it is non-empty; `ls`/`git ls-files` the real name first.
- **Long tests go to the background, with the log in a file.** The foreground tool stops at 10 minutes and kills the run (`circumstance.test.ts` takes 15 to 17, `printed-words.test.ts` 7, `early-filing-once.test.ts` 9). Run `NODE_OPTIONS=--max-old-space-size=8192 npx vitest run ... > /tmp/x.log 2>&1` as a background job, then check the log every few minutes (for example an `until grep -qE "Tests " /tmp/x.log` loop). Never switch branches while it runs, and run one heavy process at a time.
- **A review relayed by the author is not a review.** When a PR needs another session's review (`Review: lane`, `Review: words`) and the only evidence is the author quoting it, merge only if the change is a headless or test-only script, and say in the merge comment that the review was relayed.
- **Browser checks leave screenshots behind.** After any `*.browser.mjs` run, `git checkout -- .` before you commit or merge, and `pkill -x node` so the next check starts a fresh server.
- **Clear a send-back you wrote yourself.** When the builder pushes a fix to a PR you sent back and no checker has re-passed the new head, re-gate it on the merged tree yourself (the failing seed and two fresh draws) and merge; say which seed passes.
- **Compare a draw's failure on both sides with the seed.** `GOLDEN_PATH_SEED=<seed> npx vitest run <file>` on `origin/main` and on the merged branch: identical failure means main's red (name it to the CTO), a pass on one side means the PR's.
- **`eslint` with an empty file list lints the whole repository.** Build the changed-file list into a variable and run eslint only if it is non-empty (a PR of markdown and JSON only has none); the 28 errors it printed on #7059 were the repository's, not the PR's.
- **A set of heavy test files in one process kills workers.** `Worker exited unexpectedly` with some files "not run" is memory, not a failure (#7013: five core files at once). Rerun them one file at a time with `--maxWorkers=1` and report each file's own count. A `vitest` file that imports for 15 minutes (`legislature-committees.test.ts` on a busy container) is slow, not hung: leave it to finish in the background.
- **Keep every run's log, so a failure keeps its seed.** For a test that draws, run it in a loop that writes each run to its own file (`> /tmp/x_$i.log`) and read the place and seed from the failing one; a failure whose seed you did not keep cannot be sorted against main (it happened on #7073). If the test prints nothing, say that in the merge comment.
- **When two generated matrices collide, the author regenerates.** If merging main conflicts only in the effect-web or law-wiring matrices, do not hand-merge: message the lead who owns them to merge main, regenerate twice (byte-identical) and send the new head, then gate that head the same hour. The next PR that regenerates the same files needs the same again, so merge the first one fast.
- **Two merge desks on one stack: say who merges first.** When a stacked PR carries another's commits (#7047 and #7050), message the other merger which of you takes the base and wait for their word before merging the top; GitHub then shows the base as merged because its commits are on main.
- **A check that stops reporting a thing is a loosening.** When a fix makes a nightly or harness check skip a case (#7057 skips terms ended by a vacancy, #7075 treats a serving term as held), say so in the merge comment and ask the CTO for a pool item if the skipped case looks like an engine fact, as president and governor terms ending by vacancy did.
- **A conflict in a PR's generated data is the lead's, but the mechanical ones are yours.** Pool index: take main's and do not regenerate it on the branch (Nov 3, the pool conflicts line above). Stopgap rows: keep both by id and check the count of ids is unique. Everything else goes back, with the files named.

## Traps from the Nov 2 pass (Merger 0)

- **One working tree runs one branch.** Never check out another branch, or run `git merge`, in a tree where a background test is running: the run reads files as it goes (Nov 1: #7000's lender replay saw a branch switch, and #7036's tests ran on a half-merged tree with a conflicted pool index). Start a second PR in a sparse copy (`helper-checkout`: `scripts/storage/helper-checkout.sh new /home/user/<dir> <branch>`), and merge main and fix the index before you start any test.
- **Stop a background loop from its top.** A `for f in ...; do vitest run $f; done` shell moves on to the next file when you kill only the test under it. Find the loop shell's pid (`ps -eo pid,ppid,args`, the parent of the `timeout` process), kill it first, then its children, and check with `ps` that no `vitest` is left.
- **A run killed by its cap prints nothing, and nothing is not a pass.** `timeout` ends the run with no Tests line (exit 143), and a grep over its output comes back empty. Read the exit and the elapsed time, and rerun heavy files alone with a cap above their real time (law-wiring replays took 11 to 47 minutes).
- **A `Pool item:` PR whose own body says a done-when line is not done would close its item.** Edit line 1 to `Touches pool item: <id>` with `update_pull_request` (the rest of the body unchanged) and say so in the merge comment (#7088: district naming and the screenshot were still open). That is a paperwork fix, not a send-back.
- **Regenerate the law and effect matrices on every laws PR's merged tree, even when the merge was textually clean.** Main's own merges move evidence order and `crime.ts` line numbers. Check that only evidence text changed (`git diff -U0 docs/reports/law-wiring-matrix.json | grep -E '^[-+] *"status"'` prints nothing, and the "Laws wired" count is the PR's own) and commit the regeneration.
- **A lead's hold beats a checker's pass.** When a lead asks you to hold a PR (the Laws lead on #7036 for a speed fix), stop your run, push nothing, answer with what the merge will need, and take it again on the head the checker re-gates.
- **A stack is merged bottom first, and its owner is told.** When a stacked PR's base is the other merger's, message them before you merge the top, wait for their merge, then merge main into the top and merge it (Words' paper stack, #7047 under #7050). Gate the top on its whole tree: it carries the base's commits.
- **A checker's pass names a head; an author's conflict resolution is not that head.** When the author pushes a merge of main whose conflict resolution touched the PR's own file (#7032, `moves.ts`), gate it yourself on the new head. A merge-only push that leaves the PR's files unchanged keeps the pass.
- **`pool --check` flags other sessions' items on main all the time.** Name the flagged items in the merge comment as not the PR's; do not fix them in a PR you merge. Fix the ones you create yourself the same hour.
- **Single-run speed numbers wander about 10% on identical code,** and a year can read 60% high when a killed test run's worker is still going. Compare records year by year (equal counts prove a cut changed nothing), rerun an odd year alone before calling it slow, and report the 20% bar against the worst year you saw.

## Traps from the Nov 8 pass (Merge desk 2)

- **`gh api -X PUT .../merge` returns 405 "not mergeable" while the required checks (`validate`, `golden-path`) are pending; the GitHub merge tool (`merge_pull_request` with `expectedHeadSha`) merges the same head.** Use it for the pinned merge. A 405 "has merge conflicts" from the tool is main moving: fetch, merge again, re-run the fast checks, merge in the same minute. Never post "merged" before the call returns `merged: true`; one comment said "merged" over a 405 (#7761) and had to be corrected.
- **Run all of `tests/guards`, not only the families guard, on every merged tree** (`npx vitest run --dir . tests/guards`, about 90 s). #7751's new research file had no reader the guard could see (a Python script reads it) and the families guard alone did not show it. Keep a baseline from clean main (families, no-steering row counts, spelling) and name only what a PR adds. A raised `no-steering` shape count or a parameter row without a `role` is the PR's: send back.
- **Release notes get blanked by an "add the section and title" step.** Three desks' commits left notes at 0 bytes (`counter-leave-only-when-a-choice`, `screen-text-not-selectable`, `budget-hides-zero-lines`, `drive-counted-actor-filled-in`, and more), turning `release:check` red for every PR. Write the header by hand and check `wc -c` is over 0 before you push. `impact: none` carries no `section` or `title`; patch and minor need both.
- **A `Pool item:` line 1 on a PR that only adds notes or a script flips an open item to merged.** Change it to `Touches pool item:` with `update_pull_request` and say so (#7779).
- **Stacked on a merged base: retarget with the GitHub tool, not `gh api -X PATCH`** (the auto classifier refuses the shell PATCH); `update_pull_request` with `base: main` works.
- **Conflict recipes that worked.** `src/core2/data/stopgaps/gov.json` when main moved rows to another family file: take main's file and append only the PR's own rows by id. `controls.json` and `play.css` blocks that both add: keep both (a rule that ends in the shared `}` takes `}` between them). Grade files under `data/english/` (the old `grade-reach.json` is gone): never hand-merge; take main's and rerun the script that writes them (`scripts/dialogue-batch/apply-grades.ts`), or send it back to Story. `scene-talk.json` where both append rows: keep both, join with a comma, check the keys are unique. Window reads: main's scale change made `viewHeight()` the only way to read the window; a PR that still has `window.innerHeight` takes `viewHeight()`.
- **Browser checks that stop at `.travel-tile[data-filing]` or wait on `#card:not([hidden])` fail on clean main too**; run the check on main once before blaming a PR, and name it in the comment.
- **`git stash` before a checkout of main takes your uncommitted fix with it.** Commit first, or `git stash pop` right after.
- **A PR that moves an export (slim) breaks tests added on main since.** Typecheck the merged tree; the usual break is a new test importing the old path.

## Traps from the Nov 8 night (Merge desk, second account)

- **The CI check runs are a gate you can read.** `gh api repos/lamontaes/Political-Game-Git/commits/<head>/check-runs` shows `new game`, `golden-path` and `unit` for the PR's head; a green `new game` is the owner's "game opens" rule (Nov 3). `guards` and `repository` have been red on every PR with main's own reds, so compare, never read them as the PR's.
- **A patch or minor release note needs `section` and `title`; `none` carries neither.** Write the header by hand (an editor edit, never a script), then `head -8 <file>` and `wc -c <file>` (over 0) before you push. Nov 8: a one-line Python edit that opened the file for writing before reading it emptied five notes (`budget-hides-zero-lines`, `drive-counted-actor-filled-in`, `staff-cut-story-staff-after`, `no-letter-in-a-circle`, `opening-band-stopgap`) and turned `release:check` red on main for everyone until #7827 restored them. `release:check` cannot run in a shallow copy (it cannot relate the Sep 8 cutoff), so read the note's front matter yourself.
- **Typecheck a batch once.** A full typecheck takes about 8 minutes. Merge the gated PRs' heads into one throwaway branch cut from main (`git checkout -B comboN origin/main`, then `git merge` each), run typecheck and the guards once, and merge each PR pinned to its own head. If a PR's head moved while you checked, regate that one.
- **Pin the PR's remote head, not the local merged branch.** The gate branch holds your own merge of main; the merge call needs the head GitHub shows (`gh api .../pulls/N --jq .head.sha`), or the head you pushed after a micro-fix.
- **Two desks, one repository.** With an odd/even split, re-read a PR's state before every action; the other desk merges some of yours mid-gate (7796 to 7808 on Nov 8). A 405 "merge conflicts" after a sibling merge is usually `src/bench/play.mjs`: merge main again; both sides' edits are normally independent lines.
- **Do not unshallow, and never kill a fetch.** `git fetch --unshallow` writes a 4 GB temporary pack and its kill leaves `.git/shallow.lock` and the garbage behind (`rm .git/objects/pack/tmp_pack_*` and the lock once no `git fetch` is running). `--shallow-since=2026-10-20 origin main` is the deepest that works.
- **A drawn test that never finishes is a send-back.** `political-asks.test.ts` ran 29 minutes at 100% CPU on one seed (#7736). Cap runs with `timeout`, read the exit (124 is the cap), and send back the seed.
- **A `Pool item:` PR whose table says "Not met" is a `Touches` edit.** #7756 carried two done-when lines marked not met; line 1 became `Touches pool item: <id>` with `gh api -X PATCH .../pulls/N -F body=@file`.
- **Cancel stale runs with `force-cancel`.** `gh api -X POST repos/lamontaes/Political-Game-Git/actions/runs/<id>/force-cancel` for every queued `pull_request` run whose `head_sha` is not an open PR's newest commit; keep push and dispatch runs.
- **Read a PR's comments before every merge, and stay in your share.** The desks split by PR number; #7810 had been sent back by the other desk (its test fails about one run in three) and was merged anyway on Nov 8. List the PR's comments (`gh api repos/lamontaes/Political-Game-Git/issues/N/comments`) and skip any PR a sibling desk touched.
- **Gate a batch in one tree, but find whose failure it is (Merge desk 3, Nov 8).** Merging several PR heads into one throwaway branch finds conflicts and typecheck breaks in one run, but a test that fails there may belong to one PR or to main: rerun that one test on clean `origin/main` and on the PR alone before sending anything back. A merge conflict between two PRs that both append lines (skills, `build-starting-law.py` calls, `families.json` entries) is resolved by keeping both sides; a conflict in the generated `starting-law.json` or `bill-catalog.json` is resolved by running both builders and then `npx prettier --write` on the two files (the builders write one line; main holds them pretty-printed, and a diff of 35,000 deletions means you skipped the prettier step).
- **A new `src/core2` file needs a family and may need to be an entry.** The families guard fails "puts every new source file in a family" and "reaches no further inside another family" when a PR adds a file another family imports (`pay-by-quarter.ts`, `household-cost.ts` on Nov 8). Add the file to its family's `paths` and `entry` in `tests/guards/families.json`, then `node --import tsx scripts/guards/codeowners.ts`, and rerun `tests/guards/families.test.ts`; raising the baseline is never the fix.
- **`release:check` reports only its first error.** Fix one note and run it again until it prints OK; it only reads committed files, so commit the note first. An `impact: none` note carries no `section` or `title`; `patch` and `minor` need both.
- **Read the PR's base in the same call that lists it (Merge desk 3, Nov 8).** Three stacked PRs (#7921, #7906, #7895) were merged into their parent's branch instead of `main` because the listing had no `base` field and the merge call never complains, so their work never reached main; the parent's own merge had already happened. Ask for `base` with every PR list, and before each merge check `base.ref` is `main`; if it is a parent's branch whose PR is already merged, retarget the PR to `main` (`gh api -X PATCH repos/lamontaes/Political-Game-Git/pulls/N -f base=main`) and gate it again, and if the parent is still open, wait for the parent. After a batch, list the closed PRs with their bases once and look for any that are not `main`.
- **Run the English bill-sections test when the bill catalog grows.** A PR that adds a law series to `bill-catalog.json` (SSI, governor term limit on Nov 8) turns `src/english/bill-sections.test.ts` red with "needs a row" until the wording row exists; the other checks do not see it. Run that test on any PR that touches the catalog or `starting-law`.
- **A heavy test that does not finish is a send-back, with a clock.** Run each heavy test alone, with `timeout 900`, in the background, and read its CPU and RSS with `ps` after a few minutes; `climate.test.ts` ran 26 minutes at 5.9 GB on Nov 8 (three full worlds in one process) and was fixed by one small world per test.

- **A stacked PR merges into its base, not into main (Nov 9: the Small fixes session's #7895 and #7906 were stacked on other branches and "merged" without reaching main).** Before merging a PR whose base is not `main`, retarget it to main, or merge the base first; after merging, check `git branch -r --contains <merge commit>` includes `origin/main`.
- **A conflict resolved by hand in a stopgap family file or any JSON register can lose an entry without breaking the JSON (Laws and effects, Nov 9: `gov.json` and `labor.json` joins glued two entries and `SG-GOV-REACH-B-state-eitc-filing` vanished, so `stopgaps-register`, `realistic-not-real` and the unit and golden-path runs failed on #7818).** After the hand resolution, parse the file (`node -e "JSON.parse(require('fs').readFileSync('<file>','utf8'))"`), compare the id count with the two sides, and run `npx vitest run src/core2/stopgaps-register.test.ts` before pushing; a glued entry passes JSON parsing but loses an id. The guard `register-duplicate-keys` (`tests/guards/register-duplicate-keys.test.ts`, in `npm run guards`) now fails on a repeated key inside any register object and names the file and line, so run `npm run guards -- register-duplicate-keys` after the resolution too.
- **Pool notes merge as one bundle an hour (owner, Nov 11).** The CTO merges the hour's `pool/notes-<date>-<hour>` pull request on the head Desk B posted; no merger merges a pool-only pull request of its own any more. Skill `pool-notes`.
- A `validate` red whose every job is canceled (repository, guards, scope, unit) followed a base change or a newer push; it needs a re-run, not a fix. Say so once on the PR (Nov 18).
- A train PR's `repository` or `guards` red can be the base commit's, not the branch's: prettier on train files the branch never touched (the menu-test inputs, Nov 18), or the check-changes guard crashing on its `.ts` import until main's fix (#10074) is on the train. Run the check on the train's copy of the file before touching the PR.
- Once a PR is folded into the train, do not merge main into it: it makes an empty 409 and drags main's workflow and skill changes along; carry new work on a fresh branch from the train by cherry-picking your commits (CTO, Nov 18).
