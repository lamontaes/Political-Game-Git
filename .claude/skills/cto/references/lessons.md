# CTO: what the role learned, Oct 27 to 29

Part of the `cto` skill. Lessons from the role's first days.

## What the role learned, Oct 27 to 29

- **A red on main has one owner every hour** (owner, Oct 28): the merger whose merge turned it red for the first hour, then a standing red-main session with its own channel section. Read every workflow on main, not only Release.
- **Restart a line the hour its box ends.** A session that sets its item back to open is not a decision to stop the line; the next CTO pass starts a fresh session on the same item unless the owner said stop. Three lines sat idle for five hours on Oct 28 because the CTO waited for the owner's word.
- **Family batches** (owner, Oct 28): matrix lines (laws, links, traits, statistics, producers, screen points) ship one PR per family with one drawn-place proof, two Sonnet helpers per lead each on a family in its own worktree. One PR per unit stays for a finished scene, screen or law that stands alone.
- **Sessions stall on permission prompts and nobody sees it.** A cloud session that calls a scheduling tool (`send_later`, `CronCreate`), edits anything under `.git/`, or reaches outside its container waits for the owner's tap for hours. Every brief says never to; the pass checks `list_sessions` for `REQUIRES_ACTION` and clears it with `interrupt_session` plus a message.
- **A usage reset does not resume sessions.** After a limit, every session reads `FAILED` or idle; the pass sends each one "continue where you left off" by message. Scheduled tasks never deliver into a session limited to trusted devices.
- **The CI queue is a throttle at thirty merges an hour.** Main's full validation runs hourly, not per push (#6692); cancel queued runs on superseded commits; dispatch the package workflow by hand when the clock skips, and a run's publish step can sit queued for hours behind PR runs.
- **A tooling PR that unblocks everything (the pool flip, the CI queue) with every check green but main's own red is merged by the CTO under the owner's standing approval** when it has waited more than four hours on a merger; say so in the next report. Nobody merges their own feature PR.
- **The owner's voice notes are saved word for word** under `docs/coordination/voice-notes/` before anyone acts on them; a plan or a brief about words and scenes reads them, not a summary.
- **Dispatch the Mac build by hand at the end of a sitting** so what he saw fixed is in the next build he opens.
- **No wake-up timers (owner, Nov 1: "Anthropic has removed 5-hour limits, so no need for any timers or anything").** The Oct 29 wake-up chain is withdrawn: nobody arms a `send_later` or `create_trigger` to survive a reset. After a long stop, the CTO restarts the crew by message (`send_message` to each session, a line on what changed while they were down), after reading any other CTO's channel block and work orders written meanwhile.
- **Commit a coordination file to main without touching the checkout** (the channel, `MERGE-FIRST.md`, `OWNER-DECISIONS.md`, a pool item): fetch main, write the new text to the scratchpad with a quoted heredoc (`<<'EOF'`), then `GIT_INDEX_FILE=<scratch> git read-tree origin/main`, `git update-index --add --cacheinfo 100644,$(git hash-object -w <file>),<path>`, `git commit-tree $(git write-tree) -p origin/main` and push that commit to `refs/heads/main`; a rejected push means main moved, so start again from the fetch. An unquoted heredoc runs every backticked name in the text as a command and drops it without an error (Oct 30: two names vanished from a channel block); look at the pushed lines before moving on.
- **Each file you push that way starts from main's copy at push time, never your branch's.** The push replaces the whole file, so a claim or a status another session pushed after your branch was cut is silently undone. On Nov 1 a playtest push reset Words' claim on `words-address-flows-from-records` and an older `docs/pool/INDEX.md`. Before the push, for every path, `git show origin/main:<path>` against your branch's base: if it moved, redo your edit on main's copy. Never push `docs/pool/INDEX.md` this way: the Pool index workflow regenerates it from main's items after the push (Nov 3). Never build the file list from `git status` with the scratch index set: with no stat cache it hashes the whole working tree and runs for minutes.
- **Close an item by hand only when there is nothing to see in the game** (docs, skills, pool hygiene): confirm the PR that carried it merged into `main` (not into a stacked branch), then `npm run pool -- status <id> done --by=cto` and a Notes line saying what proved it. Anything a player or dev mode can see is closed by a second session's check, `npm run pool -- seen` (`done-proof` (seen-in-game part); owner's ruling, Nov 3), never on someone's word. The index's "Merged, waiting to be seen in the game" list is the queue; read it every pass and hand the oldest to a session that did not build them. A PR whose line 1 named the item but never flipped it (#6521, #6523) is closed the same way.
- **A ruling that a measurement then overturns is amended in place, not stacked** (Nov 1, the counted-voter habit): write "Amended HH:MM" under the same entry with the numbers that changed it, and tell the session the old line is withdrawn. A ruling the owner's own earlier words already answered is withdrawn the same hour, and the skill that should have found it gains the search (`look-first`, data files).
- **Load the checkers evenly by message** (`crew-coordinator` (crew-messages part)): read the open PRs by number mod 5, move the oldest from a long queue to an idle checker, and tell both. A checker already mid-gate keeps the PR.
- **Merging many skills PRs at once:** merge the ones that touch different files first, then each of the rest after merging main into its branch. Where two PRs added sections at the same spot, keep both. Where they rewrote the same line (a numbered step), keep-both duplicates it: rebuild that one line from both sides' facts (Nov 1, `session-start` steps 2 and 6). After the batch, run `npm run release:check -- --mode pr` on main as well as `test:skill-ops`: the skill test never reads declarations, and on Nov 2 two skills PRs that passed it broke the release check (an `impact: none` declaration carrying `section` and `title`, and an id an earlier release had already consumed, `skills-red-main-nov1-lessons`). Fix each on main at once: make the note bare, or rename the file and its id.

In plain words for a tool that is not Claude: "message a session" means the tool your platform gives you to reach it, or a comment on its pull request; "stop order" means the same text pushed to the leads channel and the item's pull request.
