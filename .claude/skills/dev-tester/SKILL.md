# Dev Tester

Scripts live in `scripts/dev-tests/` (`law-run.ts`, `twin.ts`, `bodies.ts`, `bribes.ts`, `vitals.ts`, `births.ts`, `summarize.mjs`). Every npm or tsx command runs with `OCD_STORAGE_OVERRIDE="cloud session, owner approved Oct 14"` and a heap of 3500 to 4500 MB; this container has 4 cores and 15 GB, so run at most three heavy processes at once or the kernel kills one without telling you.

## Method

- **Who a law reached is one read.** `lawReach(api, lawRowId, townPlaceId)` in `src/core2/law-reach/applied.ts` reads every store that records a law applied to someone (the applied table, both law-reach stores, the wage raises) and returns full people in town and elsewhere, counted people, organizations, governments and dollars by engine. Dev mode's bill card and `law-run.ts` both call it. Never count the records that cite a law: on Nov 9 that count was the 175 members who voted.
- **A forced bill says how it ended.** `billEnding(api, billId)` (legislature) names a chair's hold, a lost committee or floor vote, the Senate short of cloture, a veto or a session's end; `decideAt` returns it with `addedSections`, the sections a trade put on the bill. Discard a run whose `addedSections` is above zero, or name the rider.
- **The money check is in dev mode.** `DevMode.twinMoney()` builds the same world left alone and sums cash by holder in both; use it in place of comparing people's and organizations' cash by hand.

- **Pass a law the game's way:** `draftBill` at the body that has the power, `castMemberVote` yes for every member of every chamber (`chambersOf`), the executive's signature recorded first with `executiveDecision(api, billId, true)` (without it the executive's own stance vetoes), then `holdVote`. Dev mode's `decideAt` does the same, but it forces floor votes only: a state or federal bill can still die in a committee (`bill-failed stage "committee"`). Test city and county bodies, which have no committee, and redraw places until a state bill enacts.
- **Run to the law's own date.** A passed bill takes effect on the state's rule, often the next July 1 or 30 days on. Read the law after its effective date plus the research lag, never the day it passes.
- **Count by ids, not facts.** A printed story's id is `printed:<outlet>:law-took-effect:<law row id>` and `news.read` cites the story id. Counting records whose facts mention the law row id missed every story and wrongly reported "nobody heard" (Prairie Village KS, Nov 8).
- **A twin differs by process, not only by the law.** Any bill passing starts town halls and public comment; in Plainview TN a null bill gave 209 extra acts and 10 more people alive in 75 days. Grade on records that cite the law, and judge a law across several pairs.
- **Draw incorporated places for the city leg.** Census-designated places have no council; test the county route there.
- **Population and income checks:** use `vitals.ts` (counted households times weight, plus full people in the town); `core.people` includes officials from every other place.
- **Never switch git branches while a run writes into the repo:** `git stash -u` deleted the open output files. Write run output to the scratchpad, not the checkout.
- **Counted births and deaths:** the monthly rows exist only with bookkeeping on (`setBookkeeping(true)`); `births` and `deaths` are arrays of records.
- **Typecheck with the repo's own command.** Before any PR that touches a `.ts` file run `npm run typecheck` (about two minutes, exit code 0 and no `error TS`), never a plain `tsc --noEmit -p .` filtered for your file: the plain run is looser and let `inflow[t] += x` through, which turned main red (Nov 8, #7464). A merged type error stops everyone.
- **Memory.** Five heavy processes in a 15 GB container get killed by the kernel with no message (vitest workers vanish, drift runs stop at year 5). Run at most two or three heavy jobs, and check `pgrep` before trusting a quiet log.
- **Work in worktrees, not branch switches.** A separate worktree per branch keeps run scripts and PR branches apart; switching branches in the checkout a run reads its scripts from breaks the queued runs. Make the worktree the sparse way (`helper-checkout`: no image files, shared git objects, linked `node_modules`), never a full copy (owner, Oct 29).
- **Calibrating a model to the survey.** When one place is off (D.C. -7.1 percent a year, Futiga -5.2), print the flows by direction and reason first (`moves-probe.ts`), then fit the model's margins to the data it already holds (`mover-rates-acs-2024.json` has departures and arrivals per state); a test with a percent bound needs a place of a few thousand people.
- **Golden path: replay with the runner's place key too.** `GOLDEN_PATH_SEED` alone lets the test draw its own places; the runner also passes `GOLDEN_PATH_PLACE_KEY`. A race with several at-large seats counts a vote per seat per voter.
- **Overnight 20-year runs.** `CORE2_FAST_FORWARD=1 tsx scripts/dev-tests/drift-played.ts <seed> 20` (and `twin.ts`) takes campaign turns four times as far apart (development only; stopgap SG-SPEED-fast-forward-campaigns), so the world's elections are still decided by what campaigns leave but a larger place's 20 years fit in a night. Run it only for drift or twin questions that do not depend on the exact campaign (a law's effect on the town, deaths, moves); a question about a race's margin needs the full run, which a small town does in about 25 minutes. Run one world at a time and log to the scratchpad.
- **A golden-path run with no flags shares one 450 s budget, so a long spec "not reached" or timed out is a budget symptom, not a code failure.** `tests/golden-path/runner.mjs` gives every spec `prMilliseconds` together (the long ones last); CI splits them (`--skip-long`, and `--only-long` with `longRunningMilliseconds`, 600 s). Time the spec on its own with `GOLDEN_PATH_SEED` and `GOLDEN_PATH_PLACE_KEY` set (M0-13 is `node --max-old-space-size=8192 --expose-gc --import tsx --test-reporter=spec tests/golden-path/played-world.node-test.ts`, M1-11 is `src/bench/m1-11-check.ts`) before calling it broken; if it passes alone, the finding is how long it takes and which commits added the seconds, never a raised timeout.
- **Bisect a slowdown by timing, not by pass or fail.** Run one probe at a time on a fixed seed and place key, read the world's own duration, split halfway between the fast and slow runs, and expect a climb across several merges rather than one step (M0-13 at Margate, FL went 185, 208, 264, 270, 284, 311, 396, 400 s across one day, the last +85 s step one PR). Name the biggest steps and their sessions. A script that bisects while you do other work must not share the checkout: probe in a separate worktree, and do not pass an interrupted probe's exit code to the search.
- **A shallow clone grafts the history at its oldest commit, so `git log -- <file>` and `git log -S` blame that commit for every file.** Ask GitHub for the file's real history (`gh api -X GET repos/<owner>/<repo>/commits -f path=<file>`) or deepen with `git fetch --deepen=<n> origin main`, then bisect with `git rev-list --first-parent`. A red whose test and code have not changed for days broke by something it reads (the person card added `stage` and `grade` to what `schoolsOf` returns, #7090, and its test, untouched since Oct 28, still listed three fields).
- **Verify the test file is the branch you think it is.** After a `git checkout` to another branch a run reads that branch's test, not your edit: a "pass" can be main's old test. Print `git branch --show-current` and grep the file for a line only your edit has before reading a result.
- **Name a merge as the cause of a slowdown only from alternating pairs.** One timing of each side can swing by tens of seconds (a single probe put +27 s on #7648, a PR that touched no engine file; two alternating pairs either side of it were within 3 s). Before posting a PR as the step, time the commit before and the commit after twice each, alternating (before, after, before, after), and name it only when both pairs agree. A bisect's single probes find the neighborhood; the pairs name the PR.
- **Hourly run on fresh main (coordinator, Nov 8).** Merge main, name its commit, run `npm run guards`, then the test files no PR touched in the last 24 hours (`git log --since='24 hours ago' --name-only` on main), with vitest's default reporter and `--testTimeout=120000`. A test that hits the cap is reported "slow" with its file, never as a failure. World-playing files nobody touched run once overnight. Post each hour's reds as a comment starting "Dev Tester: red on main" with owner, place and seed, on the coordination thread (#8928, crew-wide lines only; #7365 was the line until Nov 12, 2026) and send the owning session or red main the same line (`red-main`, `crew-messages`); a red that needs a fix gets a pool item. The JSON reporter writes only at the end, so a killed run leaves nothing: use the default reporter and log to the scratchpad.
- **Before a twin pair, read the drawn place's starting law for that policy.** If the law is already in force at the start, enacting it changes nothing and the pair is not a pair (Spring Lake Park MN already had ban-the-box as its starting law, Nov 9, so both worlds ranked the same 153 applicants under it). Draw again until the starting law is the other way.
- **A test for a rare case searches draws, then skips, never passes.** When no drawn place has the case, mark the test skipped with every draw's place and count; never pass it. With cases, assert on every one. Search more draws first (up to about twelve) before skipping, and keep the skip's reason a sentence with the counts (`executive.test.ts` teens test, Nov 9, #8035: small American Samoa places had none in four draws).
