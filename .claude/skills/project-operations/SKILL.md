## Ownership and work

1. Use the existing preflight and actual repository scripts. Record absolute cwd,
   branch/head/upstream, dirty/untracked work, current writer and exact write
   scope. No new checkout or source reset just because a provider changes.
2. One full conversation is coordinator, regardless of provider. Separate full
   working conversations may receive bounded work through supported tools.
   NO subagents, recursive helpers, Browser Subagent or automatic observers.
   A message, acknowledgment, running turn and installed change are distinct.
3. Preserve and receive useful unpublished work before changing ownership.
   Reuse current source and existing controlled receiving paths; never use an
   older public snapshot to overwrite a newer local candidate. Do not stash,
   reset, clean or force-push to hide an ownership problem.
4. Run the actual changed-file/test-cadence/readiness checks for the task.
   Preserve runner exit status and actual test discovery. Keep before/after
   identity and failed/unrun tests explicit. A passing source check is not native
   play or visual acceptance. Independent full-chat review remains appropriate
   for material risk; it is not permission to spawn a hidden helper.

## PR convergence

Only the authorized coordinator/final receiver performs final integration.
Read current PR state, diff and dependencies. Classify still-active, already
received, useful unique salvage, superseded or deliberately rejected work.
Receive useful deltas into the existing current implementation, verify relevant
behavior, then close obsolete PRs with a brief rationale and receiving reference.
Do not force a merge merely to reduce a count or discard unique unreceived work.
Honor repository protections and critical data/security/compatibility blockers;
record ordinary nonblockers and keep useful coherent merges moving.

## Local RAM and process stability

Observe actual installed RAM, memory pressure, compressed/swap state and memory
of relevant local process trees at entry, before heavy jobs and at checkpoints.
Separate local Claude/Antigravity, Node, browser tests, game and Art Desk from
cloud workers. Use small non-sensitive baseline/peak/after observations. Adapt
same-host concurrency and use the existing heavy-job guard; a fixed global chat
count or free-RAM percentage alone is not a diagnosis. Clean up completed owned
browser/test processes. Checkpoint branch/head/diff/remaining steps and exact
session before safe targeted restart of a demonstrably growing process; resume
the SAME task. Logical continuous coordination does not require one immortal OS
process. Never blanket pkill/killall, capture secrets or upload heap snapshots.
No routine huge heap dumps, new AI polling service or false Mac-observation claim.
Official references: https://code.claude.com/docs/en/troubleshooting and
https://support.apple.com/guide/activity-monitor/view-memory-usage-actmntr1004/mac .
A cloud-only coordinator uses its authorized local receiver for measurements;
knowing the user's paths does not grant access.
