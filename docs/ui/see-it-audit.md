# What the simulation records about people, and what the player can see

The simulation writes dozens of kinds of records about named people and households. This audit lists them, says which screen shows each one today, and marks the ones no screen reads. In a generated Arizona world at its opening day, the player had a recorded law exposure that appeared nowhere, and none of the court events about a defendant reached the Journal. The permit denial named in the SEE-IT brief cannot be shown yet, because no code in live play writes a permit decision. The remaining unseen records are listed below with the screen each one should reach.

## How this was checked

Method (measured at main 58ba8cb0, October 8, 2026):

- Every collection of `HistoryStore` (`src/simulation/types.ts:4644`) was searched for in the three screen folders `src/presentation`, `src/player` and `src/ui`, tests excluded. A collection with no hit is listed as "no screen reader". A hit through a helper (a query function that reads the collection) counts as a reader only when a screen calls that helper.
- Writers were found by searching `src/simulation` for the function that appends to each collection.
- Events were checked against the Journal's admission rule (`src/presentation/world39-journal.ts`, function `projectWorld39Journal`): an event reaches a person's Journal only when that person's participant role starts with `agency:` or `presence:`, or the person holds an accurate direct knowledge record of it.
- One seeded world (seed `see-it-probe-1`, Arizona, town 0400730, player aged 40) was opened and read at its opening day. Advancing the same world three days stopped with `A view of an official names another person` in the official-view reflection (`src/simulation/political-belief-formation.ts:236`), the failure SOL-1258 is fixing under AU4-07. No advanced-world claim in this audit depends on that run.

Where a record's text is a sentence the simulation wrote (an event summary, a `reason`), the audit calls it record data. Where the screen would need a sentence the record does not hold, the audit marks an ENGLISH gap and does not write the line.

## Findings that change the plan

1. The News "Lately" list reads each public event and shows only a date and a place. The event summary and the law sentences are projected but not rendered, because MR-10 removed authored sentences. A line with no content is not seeing anything.
2. The Journal never shows the player's own court events, even though the Legal tab holds the same events. The Journal's admission rule excludes the `focus:` role the defendant holds.
3. A law the place began with reaches the player (the probe world recorded 170 such exposures) but the sentence builder returns nothing for it, because it needs the title of an enacted bill.
4. Views of officials are saved as private beliefs. The Journal skips them, and the dossier shows heard views only about the player.
5. The household's own bills, debts and permissions have no screen. The Personal money page shows balances, cost estimates and the mortgage only.
6. Town finances (business books, bank runs, defaults) have no screen.
7. A view a friend tells the player is saved as the fields `told-view:<teller>:<official>:<position>`, and the Journal printed those fields as "As I heard it". The Journal now leaves them out until an English bank words them. The People screen's heard-views list still shows them (about the player only).
8. A resident's environmental exposure (`environmental-condition`, written to every resident by `environment-energy-landings.ts`) has no wording in the Journal or the money page. Reading it threw `Cannot read properties of undefined (reading 'none')`, so any Journal projection or Money laws list for a resident with one would fail. Both now leave it out.
