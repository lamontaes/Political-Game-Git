# The new game still builds its opening town with the old engine

The new game reached into the old engine from 186 of its own files on October 14, 2026. After this change, 5 shipped files still do, and all 5 serve two jobs the new core has not taken over: building the opening town and the health condition pack. Everything else now reads the new core. Against main, the repository goes from 11,833 files (3,136 MB) to 10,421 (2,690 MB), and play is unchanged. The opening builder alone keeps 886 old files alive, because it builds an old-engine world and checks it with the old engine's integrity pass. Porting it belongs to OPUS-CORE, with the people pieces from OPUS-PEOPLE and the pay and jobs tables from OPUS-WORLD.

## Where the 186 files stood

Measured on the branch base (main at `23e9f580` with the dead-files cleanup merged in), with a TypeScript import walk over `src/core2`, `src/bench` and `src/director`, counting type-only and dynamic imports:

- 369 import sites in 186 files reached 74 old files.
- 91 of the 186 files ship in the game, 82 are tests and 13 are tooling.
- 9 of the 74 old files were one-line re-exports of files the core already owned (dates, ids, the seeded generator, government units, living costs, county and place-county lists, census regions).

Statuses in the table:

- **rewired**: the site now reads a new-core file that already gave the same answer. Where the core file was new to these callers, the answers were compared before switching (place search and state records on 971 cases, populations on 35,625 places, local governments on 2,213 places, and the existing parity tests for names, identities and birth dates).
- **moved**: the old code was pure data or a small helper; it now lives in the new core, verbatim, and the old engine imports it back from there (or the old copy was deleted where nothing else used it).
- **remaining port**: the old engine is the only implementation of something play uses. Nothing in this change rebuilds it.
- **parity test**: a new-core test that compares a finished port to its old original. It retires with the old file.
- **tooling**: a development generator that rebuilt a data file from old-engine sources; the data file is now the source.

What a shipped game's repository holds once the opening port is done. Nothing here is moved yet except the English engine, which this change gathered into `src/english`.

Why no rename happens in this change: `src/core2` is named in every pillar's open branch, in `AGENTS.md`, in the speed guard's path filter (`.github/workflows/m0-guard.yml`) and in about 1,500 import lines. Renaming it while five sessions write to it would put a conflict in every open pull request at once. So it is a pure rename the CTO schedules for a quiet hour after the opening port lands, as one commit with the guards run before and after. `src/bench` to `src/play` is the same: PLAY's branch writes there all day.

## Method

A TypeScript-compiler walk of every `import`, `export … from`, dynamic `import()` and `import("…")` type in `src/core2`, `src/bench` and `src/director`, resolved to files, on the branch base before any change. Runtime footprints come from an esbuild bundle of each old file's used exports with every module marked free of side effects. The answers of new-core replacements were compared to the old functions in a one-off script before each switch.
