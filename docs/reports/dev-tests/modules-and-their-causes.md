# Modules the one-year played-world check finds idle, and the cause each waits for

Written by the Dev Tester, Nov 8, 2026, from golden-path M0-13 "every module" runs in three drawn worlds (seed d0370733eed7f478f752c75c6aef4f1f2622b4f4de7f2e495c0111257798106f and two random seeds) and a read of each module's header. The test's rule is unchanged (the CTO's call); this is the list the ruling needs. Replay: `GOLDEN_PATH_SEED=<seed> node --max-old-space-size=7000 --expose-gc --import tsx tests/golden-path/played-world.node-test.ts`.

Three kinds of module show as idle: static data loaded at the opening, modules that wait for a cause that may not arise in one year, and modules whose cause is a person's act.

What follows from this: no module on the list is uninstalled; each is quiet because nothing in a one-year, one-town run gives it a cause. Whether such a module should read "unobserved" instead of BROKEN is a ruling on the M0-13 rule, not a wiring change. The one real engine gap found is ballot measures: with no emergent cause, after the real list is exhausted a place can never vote on a measure (sent to Laws and effects).
