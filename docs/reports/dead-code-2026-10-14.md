# About 520 old files can go today, and 1,220 more after one porting job

The new game reaches 2,048 of the 2,568 files under the source folder. The other 520 files (8.2 MB) are dead. 139 of them (1.5 MB) can be deleted today with no other change. The other 381 (6.7 MB) are used only by old data, art and prose tooling, so they go when you retire those commands. The bigger prize is a tangle of 886 old-engine files the new game still loads. Porting about 44 old functions into the new core would free 1,220 more files (35.8 MB) and leave 61 old files to move. One thing needs a decision before release: the production build points at two app files that no longer exist.

## Method and what could not be verified

The walk starts from a scratch copy of `scripts/dead-code/reachable.mjs`. Its entry points are the new-game folders without their tests, plus the commands the two workflows and `build:steps` run: the zero-dice guard, the spelling check, the typecheck scripts, the manifest checks, the American English tests, and the core guard, report check and storage tools. Tests travel with the file they test. Type-only imports are counted, because typecheck needs them. A runtime-only walk keeps the same 886-file tangle.

Not verified:

- No build, typecheck or golden-path run after a trial deletion. The counts are a static walk.
- Paths built at run time from variables can hide a reader. Only the map folder was found and corrected by hand.
- The 162 browser specs were not opened one by one; they were judged by their target page.
- Whether the old data pipeline, art desk and prose tooling should stay is your call. They are reported, not judged.
