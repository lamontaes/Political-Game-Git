# Graphics and pose production convergence

Status: **implemented on `claude/graphics-pose-production-convergence`, awaiting
independent code audit and human visual acceptance**

Authority: Drive packet `50_CLAUDE_MODULAR_PERSON_POSE_LIBRARY_AND_RUNTIME_PRODUCTION_MEGA_PATCH`,
which supersedes packet 45. Base: accepted main `c90e351`.

## What this branch is

One graphics authority instead of a permanent stack, plus the pose contract the
modular person system was blocked on.

### Part I — convergence

- The useful architecture of PR #63 and PR #74 is carried onto this single
  branch from accepted main: scene registry and placement, raster tiers,
  component masters, measured geometry, scene scaffold, semantic context, tier
  plans, dynamic environment surfaces, the debug overlay and both proof
  surfaces. Neither stacked PR remains an authority.
- Twenty-five source masters are re-homed from the superseded PR #48 under
  Drive authority 42, with hashes, provenance and re-cut identifiers. Its
  thirty-five normalized derivatives are rejected with measurements.
- Every disposition — branch cargo and downloaded packs — is recorded in a
  validated ledger that cannot claim anything nobody measured.
- The approved environment library becomes production-authoring records: three
  new families and a declared intake queue that asserts no measurement.
- Surface slots get a closed vocabulary, a salience floor for dynamic content,
  and a canonical-source-only policy for civic symbols.

### Part II — the pose system

- One pose contract extending the modular character contract, not a parallel
  schema: posture class, facing, root, contacts, eighteen landmarks,
  compatibility, canvas and master minimum, production status, provenance,
  human-QA state and contact verification.
- Scene anchors resolve a posture through the registry, and a missing pose is a
  named compatibility gap rather than a silent substitution.
- Deterministic control plates generated from the landmarks, re-derived by
  validation.
- A pose and contact proof section inside the existing scene proof.

### Part III — inventory

- A generated asset bank inventory and generation queue, regenerated by test.

## What this branch deliberately does not do

- No Blender, no manual 3D posing, no skeletal runtime, no extraction of static
  frames from animation rigs.
- No new character art is generated. The exact briefs for the missing P0 poses
  are in the Drive report `50B_CLAUDE_P0_POSE_GENERATION_GUIDE_AND_MISSING_ASSET_QUEUE`.
- No change to PlayerGame, persistence, legislation, name generation or the
  Packet 36 source domains. The ownership boundary is an executable test.
- No auto-merge. The PR stays open for independent audit and human visual
  acceptance.

## Human visual acceptance

The ten acceptance questions in the packet are answered against
`?view=scene-proof`, which carries both the scene placement proof and the pose
and contact proof. The one that cannot pass yet is coverage: two of the four P0
pose families have no art at all, and the proof says so rather than hiding it.
