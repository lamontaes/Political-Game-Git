## Consumer contract

`JudicialOfficeWork` accepts the current `world`, canonical
`courtOrganizationId`, and the root `onWorldChange`. An optional `onPerson`
callback carries exact stable participant IDs to UI-core's person route; when
no route is supplied, names are text rather than dead controls. Pass the root's
`transitionHandlers` if it supplies a nonempty future-due registry. No private
save store, hidden context switch or render-time intake.

`initializeJudicialOfficePractice` must run only from explicit Custom Begin.
`judicialOfficeContexts` discovers current practice roles on load; it cannot
infer authority from a name or title. `receiveNextJudicialOfficeWork` is an
explicit check-correspondence action, not an effect fired when Work opens.

Click path after integration: Custom Start → age 25 or older → Judicial office
practice → Begin → finish the normal introduction → Work → Check office
correspondence → choose a response → Prepare the follow-up note → save/load.
The six office adaptations are not the full underlying scenarios. Four compiled
intakes and fifty other bank rows retain exact mechanic blockers. No case,
motion, ruling, remedy, recusal, reassignment, selection law or outcome score.
