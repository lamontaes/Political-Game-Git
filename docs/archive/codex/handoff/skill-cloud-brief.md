# Brief a team (Lamontae: "bounded, specific, fleshed out ... work smarter")

Every brief has, in order:

1. The first line: "You are CLOUD X. <one-sentence job>." (only the first line previews).
2. From, time, and whether it replaces earlier work.
3. WHAT AND WHY: Lamontae's own words where they exist, and the player-visible goal.
4. STEPS: numbered, each concrete. Name the files to read first, the records to reuse, and the research sources (primary pages; curl works where fetch is blocked).
5. BOUNDS: what not to touch (other teams' files, art/people-engine images, PG-LAND). No scripting of emergent phenomena (build the mechanisms). One rule for all places. UNKNOWN is never zero.
6. CHECKPOINT: when to post research or a design for approval. Big designs go to Lamontae as an artifact through Claude CTO; no code before his yes.
7. ENDPOINT: "done when …", measured in a watched world or a test, then PR, gate, and VALIDATED in the 03 doc.
8. Report placeholders added.

Send it with SendMessage to "Team X standby". For long briefs, append the text to 04 CLOUD TEAM BRIEFS and send a short message pointing at it. Add the job to 06 SHARED WORK QUEUE (or mark it claimed) and to cto-notes/TALLY.md.
