## Rules for every Codex package

- **Read first.** `AGENTS.md`, then this file, then the skills your package names, by path (`.agents/skills/<name>/SKILL.md`). Codex does not load skills by itself.
- **Environment.** Run every npm command with `OCD_STORAGE_OVERRIDE="cloud session, owner approved Oct 14"` and `NODE_OPTIONS=--max-old-space-size=8192`. One heavy process at a time. Fetch full history before `release:check` (`git fetch --deepen=3000 origin main`).
- **Claim, then build.** Before building an item, run `npm run pool -- claim <id> --branch codex/<package>-<slug>`. Branches start with `codex/`. Never touch a branch or an item another session holds.
- **You run your own gate.** No Claude checker is running, so you run the checker skill's "The check" list on your merged result before you open a pull request. That is typecheck, eslint and prettier on changed files, `release:check --mode pr`, `zero-dice`, `pool --check` and `guards`. Each new or changed test runs on three fresh drawn places, with the seeds named.
- **The pull request.** Open it ready, following `.github/PULL_REQUEST_TEMPLATE.md`: line 1 `Pool item: <id>`, the gate line, what changed for the player, the Done when table with evidence (place, seed, record ids), what was removed. Never merge your own pull request; Package A merges it.

- **Report.** Add a block at the top of a `## Codex` section in `docs/coordination/LEADS-2026-10-24.md` (create the section above `## CTO` if it is missing) every two hours and when you stop: package letter, items done with PR numbers, items in progress with their branch, anything you found.
