# Government work: dependencies and remaining parts

Government work is spread across unfinished series and older pull requests. This map identifies the recorded contracts each later part consumes, preserves existing work, and separates merged receipts from an endpoint that still needs a code audit. Committees and leadership come first, then constituent cases, election night, and bargaining. The package is not complete.

## How to use the map

Resume the earliest unmerged contract in each family. Reuse an existing part branch or pull request rather than create a second writer. A merged receipt proves that change landed; it does not prove every acceptance condition in the brief. A POOL status alone is not a live-play receipt. Closed unmerged requests are history, not completion. Endpoint wording and ownership notes are historical POOL instructions, not current ownership findings. Dependencies below describe record contracts inferred from the linked briefs; validate the consumer in code before editing it.

The [current POOL snapshot](https://github.com/lamontaes/Political-Game-Git/blob/9505c885afe5a12050795d3aa2d9b54ae79d0a60/docs/codex/assignments/POOL.md) lists 205 b-series parts across 32 families, rather than the package header's historical 165 open parts. Families b33–b49 have briefs but no b-series part rows in this POOL snapshot; do not silently create new parts for them. Every listed family remains subject to its final-part endpoint audit. No family is declared unsupported merely because data or a producer is missing.

No SPEED FIXED ruling was found in the 00q log read for this inventory. The [00s package testing rule](https://docs.google.com/document/d/16PfU1AVhbXYtMJ-DKXk8U4vYRDIjz0GulISsxT6zGLw/edit) and the OPUS CTO 11:10 a.m. instruction in [00q](https://docs.google.com/document/d/1DpVG1S39-SY7ZrJ38_3HEnd7QxYBqcaVFs-D5nh7k-M/edit) govern these limits. Checks stay table-driven or unit-level. At most one seeded world may advance seven simulated days, and no test file may exceed five minutes.
