Audit basis: checkout HEAD `fa781e963e15ee2343be44fd71e631930ea63f76`. ## Duplicate inventory

- Shared measure-step engine: `applyInstitutionStep` in `governing/legislative-clock.ts`; shared multi-measure sitting orchestrator: `legislativeSittingHandler` in `governing/legislative-sittings.ts`.
- Separate sitting entry points and calendars remain for Congress (`congressSittingHandler`, `scheduleCongressSitting`), D.C. (`dcCouncilSittingHandler`, `scheduleDcCouncilSitting`), local councils (`localCouncilMeetingHandler`, local meeting scheduler), and state legislatures (`stateLegislatureWakeHandler` / state governing transitions).
- Separate intake/filing and executive/override seams remain by level. These are not duplicate copies of the shared measure-step loop, but they prevent the requested single handler from being the sole lifecycle owner.
- Local ordinance reading and enactment still have a dedicated path (`decideOrdinaryCouncilReading`, `municipal-ordinance-procedure.ts`), so city ordinance progression is not fully covered by the shared legislative path.
- No county legislative body is currently represented in these audited paths.

This is a code-path audit, not a claim that county legislative institutions have no real-world authority. The game currently has no distinct county legislative body in these paths.
