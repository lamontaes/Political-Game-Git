# A successor taking office closes the predecessor’s clemency request

Before: A saved request could remain open after the governor who received it left office. The entry writers did not wake that request.

After: Both actual entry paths review existing requests immediately. A request to the outgoing governor lapses and stays addressed to that governor. The successor receives no transferred request.

## 1. Why-chain

The request lapses because its asked-holder differs from the actual entering executive. The entering person comes from a recorded contest, dated term, qualification, and active work status. Both production entry writers have already checked their applicable qualification, life, and status guards. The existing clemency writer records lapse without making a second decision. Bedrock: the saved request is addressed to one actual person; this is the existing game rule, not a measured grant rate. New requests remain on their existing caller.

## 2. Research

No new amount, waiting period, grant rate, or jurisdictional power is introduced. The existing clemency authority data determines supported executive places. This implements the approved asked-holder rule and explicit activation seams. Existing board and prosecution timing stand-ins remain unrecalibrated.

## 3. Revisions

The general office reader recognizes a dated entry only after its due item resolves, and late entry only after its historical event is saved. At the released post-active-write hook, the adapter therefore passes the validated actual term holder to the existing petition writer. This preserves both caller sequences without moving their events or inventing an office desk.

## 4. What gets built

1. Export `advanceClemencyAfterExecutiveEntry(world, relationshipId)` from the owned clemency module.
2. Add only its import and post-active-write call to both released entry seams.
3. Preserve the original request, guards, expiry, governing scheduling, late-entry event, and weekly fallback.

## 5. Simulated, records, world pieces, checks

SIMULATED: no new actor decision or evaluator. RECORDS: the existing lapse and knowledge writers append their normal records. WORLD PIECES: actual contest, term, qualification, living winner, active work, and saved petition are required. Expected-only work cannot review a petition. CHECKS: no transfer, unchanged original request, one lapse, canonical reload, and repeat safety. Opening/load recovery remains Audit-owned.

## 6. Proof run

Measured: 15 tests passed across Iowa, Louisiana, Texas, North Dakota, and New Jersey. The place permutation came from all 56 jurisdictions with seed `team9-g10-floor-five-20260930`, filtered only for actual supported executive authority. Each place covers native dated-entry dispatch, actual late qualification, and the expected-only guard. Both activation cases check reload and replay. The run used authored recorded contests and term boundaries, with unrelated due items isolated. It does not prove an ordinary campaign or statewide grant totals.

Measured: the four owned TypeScript roots have zero errors. ESLint, Prettier, and diff checks passed. Zero-dice reports zero new findings and five inherited gone entries. The previous 17-case batch, whole suite, browser, year-speed comparison, and final-main checks were not run.

## 7. Worked example

In US-IA, Kendall Sharpe had a saved request addressed to Keith Knight. Manuel Sharpe entered through actual saved term work. The existing writer appended lapse event `event_cdfca43c8be68af2`. Request `event_965d733c27c36ea9` stayed unchanged. No clemency matter transferred to the successor, and reload plus repeat added no second lapse. No money moves in this hook.
