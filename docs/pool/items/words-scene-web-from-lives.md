**What.** The owner, Oct 27: "all those scenes that I said, you should be able to find variants... a victory speech after a campaign obviously means there needs to be a concession speech. What happens during the victory speech? Then you look at real life ones... they had a contentious call with the other candidate, or this other person in this state had this one unique experience, and that can be a branch... This can be a rich game just by using the real lives of people. You should be using hundreds of people for this... built into a system, like the effects web." This item builds the scene web: one matrix row per scene type and variant, like `docs/reports/law-wiring-matrix.json` for laws. Each row: the scene (from `docs/design/scenes/owner-scene-examples.md`, 112 entries, 36 with nothing behind them), its variants (the mirror scene, the branches real lives show), the real-life episodes that calibrate it (slug into `docs/design/scenes/from-life/`, never a real name in player text), its trigger record, the situation type that fires it, its bank of lines and how many versions per speaker, whether it fires in a played year in a drawn place, and the owner's grade if any. The matrix is regenerated by a script from `situation-types.json`, the banks and a played year, never written by hand, and written to `docs/reports/scene-web.json` and `.md`, so each morning the owner can read what scenes exist, what was generated overnight, and what is still missing. This is an L item: the claimer splits it into one bounded item per domain (home and family; meeting people and places; the campaign; election day and night; legislating at council, county, state and Congress; the executive as mayor, county, governor and president; constituents and cases; donors and corruption; the press) before building, each domain in every state from its data (owner, Oct 27: "there is infinitely more" than the campaign), each with its own done-when, and this item becomes `blocked-on` its parts.

**Rules.** Serves `scenes-from-life` and `scene-standard` (a scene writes something back; roles cast from the world; lines vary by trait and tie); LAW.md §4. Wire to the world: every row names its trigger record and outcome record. Ask why: a quiet stretch in a played year is a missing row, named. No dice: a variant fires from its cause. One rule, all 56 places: the played year is a drawn place. Replace, never layer: the matrix replaces the hand lists of scene types in `docs/design/story-director.md`.

**Done when.** `npm run scene-web` (a new script under `scripts/`) regenerates `docs/reports/scene-web.json` and `.md` from `src/director/data/situation-types.json`, `data/english/parts/` and one played year in a drawn place (`buildBenchWorld`, place and seed named), with one row per scene type and variant, each row naming its trigger record kind, its outcome record kind, its episode slugs, its line count per speaker, and fired or not; every one of the 112 owner examples maps to a row or to a `missing` row with the owner's quote; the report's `missing` count is the morning number the CTO reports; the script fails if a situation type has no row or a row has no episode.

**Time box.** 3 hours for the split and the script's first run with the rows that exist; each part item then carries its own box.

**You will see.** Each morning a list of every kind of scene the game can play, which ones played overnight in a drawn town, and which ones are still missing, by name.
