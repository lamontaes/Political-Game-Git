**What.** From Nov 13 to 16, 258 test files on main were pinned: 110 had their drawn seed taken out and 212 gained a fixed place or seed. A pinned test checks one place, so a fault in another place never shows. The owner's answer is "be random with it".
Seen: the check-changes guard's findings between main at 0a871a98 (Nov 12) and main on Nov 17.

**Cause.** Design: the Account lead's pinned-tests rulings of Nov 13 to 15 (skill pinned-tests) pinned every test that gates a pull request; the owner's Nov 16 answer on issue 9747, section 7, "be random with it", replaces them, and the CTO's rule 1 on the same issue refuses a new pin without a CTO line.

**Fix.** File by file, following skill drawn-place-tests, "Putting a pinned test back on a drawn place": bring back the drawn seed line and the drawn version's own limit, make draw 0 the seed itself, replay the old pinned seed, and print the place used and what was passed over. A file whose draw then fails is a fault to fix at its cause, never a reason to pin it again. The player sees nothing; the tests see every place.

**Time box.** 2 hours a batch of about 25 files, with each file's run.

**Rules.** One rule, all 56 places: a test draws its place from all 56 and names the place and seed it used. No dice: a draw picks only which world exists, never an outcome.

**Done when.** A second session runs the check-changes guard from main at 0a871a98 to main and finds no file still pinned, and runs each unpinned file once on a fresh draw, for example in a drawn place, Daniel, Utah (seed pin-bill-address), recording the place and seed each used.

**Waits on.** The CTO's line on whether a pull request that puts a drawn seed back may drop the case that only checked the pinned place (asked on issue 9747).

**Files.** scripts/guards/check-changes.mjs (new), src/bench/bill-address.test.ts and the other files listed by folder in the Notes.
