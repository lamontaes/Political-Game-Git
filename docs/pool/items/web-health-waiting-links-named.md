**What.** Sixteen of the health family's 28 outcome-web links do not reach a person's records. The health engine already registers why, in four stopgaps (a condition record, unsized links, person-level causes, coverage), but their text names the causes in prose rather than by link key, so the matrix files every one of the sixteen under a shared, generic unread row. This item makes each waiting link name its specific stopgap and adds a test that holds each reason, so the day an engine reads one of these outcomes the test says to wire the link. The played-year proofs of the twelve health links that reach stay with web-reach-health.

**Rules.** An effect is a read, not a record: a link stays on the unwired list until an engine reads its outcome when it decides or pays, and its stopgap says exactly what is missing. This is a game, not a spreadsheet: no new condition, record or mechanic is added to make a link reach.

**Done when.** In src/core2/data/outcome-web/unwired.json each of the sixteen waiting health links cites one of the health engine's specific stopgaps (SG-EW-HEALTH-condition-record, -unsized-links or -person-level), regenerated by write-unwired.ts; a test in src/core2 holds each link's reason and fails when an engine reads its outcome or when its stopgap no longer names it; and outcome-web-unwired.test.ts passes.

**Files.** src/core2/data/stopgaps.json, src/core2/data/outcome-web/unwired.json, src/core2/outcome-web-health-waiting.test.ts
