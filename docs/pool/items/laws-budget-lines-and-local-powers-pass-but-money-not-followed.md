**What.** Three kinds of law in dev mode's list have been shown to pass and nothing more. In the law sweep in Marion, Mississippi (seed 7df73e53cd67), the audit set budget lines, and amounts with no value in force at a body, to 1 of whatever unit they use, which proves a bill passes and nothing more. The same goes for the 60 grants of power to local government, which the audit did not follow into a town using the power. Dev mode lists 170 laws there: 37 amounts, 73 yes-or-no questions and 60 grants. The audit's call: "do not count any of them as working until someone follows the money the same way." So none of these may be counted as working today. Run the sweep's twin-world money trace on each of them, with a real change in place of 1 unit: a budget line moved by a share of its size, an amount set where none was in force at a value a real place uses, and each grant followed into a town that then uses the power. File every law whose money does not move, or moves the wrong way, as its own item with its figures, and fix the ones whose cause is a missing or broken read.

**Time box.** 10 hours for one Sonnet session. When it runs out, push what passes, set the state honestly with a one-line note, and stop.

**Rules.** The chain is the acceptance: a budget line or a grant is finished only when one dollar or one rule is followed to a named person and back out, by record id; a bill that passes is not that. An effect is a read, not a record: a law row another engine never reads when it decides or pays is a placeholder, however many reach rows it writes. Wire to the world: the result is stated for the whole family (every budget line, every grant), not for a chosen example. One rule, all 56 places: a grant is followed in a place whose own state law lets the town use it, found from the place's data. Owner, November 8, quoted by the audit: "when it finds these errors or finds that these laws don't pass, I want them fixed. I don't just want a report of everything that was broken."

**Done when.** A matrix in the PR body has one row for every budget line, every amount that had no value in force at the body, and each of the 60 grants of local power, each row filled from the running game by a session that did not build the fix. For each row: start the bench (`OCD_STORAGE_OVERRIDE="cloud session, owner approved Oct 14" npm run bench`, play at `/play`) in a drawn place whose body may pass it, written down with its seed; introduce a one-section bill with dev mode's own controls (the Bills panel on the Government screen: Body, Sponsor, Law, Value or Answer, Introduce, Chair hears the bill, Margin 3, Executive: Signs, Pass), confirm on the bill page that it left with one section, and run 120 days at a local body or 180 at a state or Congress in the Run panel. For a grant, then pass the town's own bill that uses the power and run the same days again. Run a second game on the same place and seed with no bill for the same days, and compare every cash account in the two worlds (full people in town, counted households, businesses, each government's treasury and the outside account). Each row records the totals, the direction the law implies, the payer named by the payment's own label, and one record id the law reached, or "moved nothing" with the reason. The script route for the same pairs is `OCD_STORAGE_OVERRIDE="cloud session, owner approved Oct 14" node --max-old-space-size=4500 --import tsx scripts/dev-tests/law-run.ts <seed> <city|county|state|federal> <policy id part> <days>`, one heavy run at a time. Then the rows are run again as a named repro in Marion, Mississippi, seed 7df73e53cd67. Every row that moved nothing or pointed the wrong way has its own pool item, by id, and a test in a drawn place covers each fix made here. The owner plays it: he passes a budget line or uses a power his state granted, and a screenshot of the town a season later shows whose money changed.

**Notes.** From the Fable audit, Pillar 2 ("What I did not test here") and its closing list: "What budget lines, amounts with no value in force at a body, and the 60 grants of local power do once passed. The sweep proved only that they pass." Nothing here is a measured defect yet; it is untested ground, filed so that nobody counts it as working. Checked on main, Nov 10: the bill catalog holds 60 `law:local-power:` policies, matching the audit's 60, and 23 budget-line policies. Two things to settle first. Dev mode's `introduce` builds only an amount or a yes-or-no section, and `lawSeriesCatalog` leaves the catalog's budget-line policies out of dev mode's law list, so on main a spending line cannot be introduced from the dev Bills panel; the audit does not say how its sweep reached budget lines, and they may be among its 37 amounts under another series. Either add budget lines to dev mode's one introduce route as part of this item, or draft them from a seat taken through Advanced, Play as, and force the vote from the bill page's dev card. And both dev mode and the harness add riders when votes are forced (`gov-riders-added-when-every-vote-is-forced`), so every pair must name the sections its bill left with. The audit's by-account sums came from its own script, which is not in the repository; `law-run.ts` prints people's cash and organizations' cash against its control and does not split counted households or governments, so the split is part of the work. If the matrix is more than one session can fill, split it by kind (budget lines, unset amounts, grants) into three items before building.
