**What.** Dev mode's Scenes panel on the Calendar is a row of plain buttons, one per kind of scene, and a Make it happen button. It does not say which kinds it can cause. Measured by the Nov 9 audit: the panel showed 98 buttons for the 99 kinds dev mode lists, of which dev mode can directly cause 6, for 92 it runs the world and waits, and one cannot be caused at all; in Ten Broeck, Kentucky (no seed) a "visit" began and played nothing in four days, and four waited-for scenes (a concession call, a farewell, an argument, a new friendship) each ran a full game year and never happened. The status report still says dev mode can force "79 of 97 kinds" (docs/reports/rulings-check-2026-11-08.md, line 47). The counts have moved since: read on Nov 10 from the situation-types table there are 102 distinct kinds, 6 with a direct way in, 96 that wait and 1 with none. Fix it for every kind from the same table the director reads.

**Cause.** Found in code: `scenes()` in src/bench/dev-mode.ts (line 1254) gives each kind a way in (`SCENE_RECIPES`, line 123, an engine's own function; a wait on a record or a ledger moment through `forceScene`, line 1344; or none); `devScenePanel` in src/bench/ui/dev-scene.mjs (line 29) drops the kinds with no way in, lists the rest by key alone and prints 'Begun for' (`labels.begun`, line 142) whatever happened, even when the run ended at its cap with nothing found. Measured by the Nov 9 audit (98 buttons for 99 kinds, 6 directly causable; Ten Broeck, Kentucky, no seed).

**Fix.** Show every kind in one of three states (plays now, waits for a record, cannot be caused) from the same table the director reads, grouped under three headings with no caption under any button; name the awaited record in the result line, say when the run ended at its cap with nothing found and how many days ran, and replace the '79 of 97' line in docs/reports/rulings-check-2026-11-08.md with the measured counts, their date and the commit. File one item per kind whose awaited record no engine writes for the player (a producer gap for the director lead); do not build those here.

**Time box.** 8 hours for one Sonnet session. When it runs out, push what passes, set the state honestly with a one-line note, and stop.

**Rules.** Ask why: a scene that does not play must name the record it is waiting for, by kind, and a run that ends without it must say so in the result line. Wire to the world: every kind is caused through the engine that writes its cause record, never by a dev-made moment, so the list reports what the engines can do today and hides nothing. Owner, Nov 8, on dev mode: "Making it happen should just trigger the code in the game that makes it happen." Owner, Nov 8, on scenes: every kind working, then "30 different scenes within there." Owner, Nov 8, about 2:15 a.m., on the dev mode mocks: "remove all those subtexts", which the panel's code cites as its reason for showing names alone; so the three states are shown without a caption line under any button (for example the kinds grouped under three headings, and the waited-for record named in the panel's one result line).

**Done when.** A second session starts the bench (`npm run bench`, `/play`), leaves the Place field empty so the place is drawn, writes down the place and seed the title shows, turns Dev mode on in Options and opens the Calendar. In the Scenes panel every kind dev mode lists is shown in one of three states: plays now, waits for a record, cannot be caused. The number in each state equals what a test beside `src/bench/dev-scene.test.ts` prints from `scenes()` for that drawn place and seed. It picks one plays-now kind for the player, presses Make it happen, then runs until "A scene fires": that scene opens on screen, or the result line says in words what it still waits for. It picks one waiting kind: the result line names the record kind it waits for, and when the run ends at its cap the line says the record never came and how many days ran, never "Begun for". The kind that cannot be caused is listed as such and cannot be started. It saves a screenshot of the panel and of each result line with the place and seed under it. It then repeats in Ten Broeck, Kentucky (the audit's place; no seed was given, so the seed drawn is written down): it asks for a "visit", and either the visit plays or the line says what it waits for. The line in `docs/reports/rulings-check-2026-11-08.md` that reads "79 of 97 kinds" is replaced by the three measured counts with the date and the commit they were read on. The owner plays it: with Dev mode on he opens Scenes, sees at a glance which scenes he can make happen today, and is told what any other scene is waiting for.
