# Civilian career providers

CAREER-PATH7 composes LIFE #141 through feature-local providers. Organizations,
WorkRelationship, WorkStatus, WorkRole, EducationEnrollment, ScheduledActivity,
ResourceFlow, FutureDueItem, transfer outcomes and private WorldEvent histories
remain canonical. There is no new World, credential table, scheduler or staffing
allocator. App, PlayerGame and global navigation remain UI-owned.

An explicit inquiry materializes a fictional cooperative and its authored offer
through canonical writers. The occupation code never names that employer.
Acceptance records consent but leaves work expected until its future start date.
Beginning work rechecks current prerequisites. Reads create nothing. Refusal
and resignation retain history; resignation cancels future shifts but preserves
earned compensation. LIFE's existing pay handler settles each attended shift on
the following day using its historical contract terms and actual recipient.

The source domain compiles all 1,016 O*NET-SOC2019 identities, all 18,838 published
O*NET31 task statements, the full official crosswalk and final SOC2018 hierarchy,
and applicable national May2025 OEWS observations. The source lock records exact
retrievals, raw hashes, editions and rights. Core production capabilities reject
missing, quarantined, mismatched and unknown-rights artifacts. Compiler headers,
1,016 identities, 867 SOC detailed occupations and complete joins are checked.
The final SOC workbook is soc_structure_2018.xlsx; the older similarly named
soc_2018_structure.xlsx contains a proposed structure and is not used.

Source observations retain U.S. geography, reference period and published-estimate
status. Wage cells retain publisher strings, including suppression/nonavailability
markers, and null remains distinct from zero. No county estimate or historical
individual salary is inferred. The browser projection is replayed from locked
bytes and contains every task in the three existing LIFE contexts: 24 retail,
20 office and 18 machinery-maintenance tasks. Raw national source availability
does not imply all occupations have an authored employer pathway.

The selected responsibility is preserved with its source version/task ID and
scheduled activity. A completed shift retains the player's submitted work and
an activity-linked work record. Two completed records in the same engagement
permit an explicit expanded-responsibility agreement. This is authored employer
progression, never professional licensure. Quality judgments and named supervisor
feedback are not invented. The work record remains usable after resignation.

LIFE's completed-enrollment query supplies qualifications. EDU's new noncredit
programs do not substitute for an office/repair certificate or legal license.
Public employment remains excluded pending CIVIL's dated class/authority seam.
No reporter or colleague is synthesized for NEWS integration.

## Architecture audit and LEARN

- Identity/version: stable work and organization roots persist; provider IDs
  are pinned in work stable keys and source versions appear in offered/planned
  records. Later role changes append rather than rewrite.
- Time/pay: schedule and performance delegate to LIFE; exact scheduled minutes
  and due-date pay remain under existing canonical writers. Repeated completion
  and invalid offers refuse without writes.
- Knowledge: work records are private and involve the actual controlled worker.
  Public source context is separate from biography and named employer identity.
- Source boundary: Node-only domain/compiler use existing core capabilities;
  browser consumers import only generated JSON. No simulation imports source.
- Credentials/public authority: existing prerequisites are consumed; directory
  and customary-education facts do not grant credentials or public hiring power.
- Retroactive compatibility: accepted LIFE interfaces and allocator preserved.
  Its published dependency is explicitly composed, not represented as merged.
- LEARN: official-looking filenames and HTTP200 are insufficient acquisition
  proof. Exact final-table headers and official crosswalk coverage now reject
  the wrong structure and a non-workbook response before runtime projection.

Acceptance requires UI application and actual normal-route pointer/keyboard and
save proof. Unit tests and this audit do not imply human visual acceptance.
