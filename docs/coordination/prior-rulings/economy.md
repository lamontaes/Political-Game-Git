## Conflicts

### A. Missing values: "estimate, never UNKNOWN" versus "missing stays missing" and "unresolved, transfer nothing"

- Older, 2026-09-15 (R23): "Missing observations remain missing. They do not become zero, an invented estimate or a graph line that conceals the gap."
- Older, 2026-09-26 (R11): "Unknown is never zero, and there is no fallback." For a payment with no recorded balance or an unknown tax amount, return an explicit unresolved result and transfer nothing.
- Newer, 2026-09-28 (R8): "no value may show as unknown; an unread legal rule starts from the most common real rule."
- Newer, 2026-09-29 (R6): "estimate never UNKNOWN is standing law."
- Also 2026-09-28 (R10), 04 SYSTEM SPECS: "Where no research exists, UNKNOWN, never a copy of a state." This is a conflict within the same doc and with R6 and R8.

Verdict under the owner's rule: the newest rulings (R6, R8, September 28 and 29) win for values a player sees. For money settlement, R11 (September 26) is specific to payments and still the only rule covering what the code does when a payer has no balance, and it may still stand. The owner should confirm which applies to money transfers.

Note: The older rule is the only one that clearly makes sense for observed data (a real count that nobody measured). The newer rule makes sense for estimates. Both could hold if the rule were split: observed data stays missing, and displayed estimates start from the average. The owner has not said this.
