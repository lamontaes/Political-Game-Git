## What the screens engine is (the CTO's definition)

The interface:

- **the client:** play.mjs and the ui kit, which draw every menu, card, board, talk box and panel;
- **the play server's route table** (handler.ts): what the client may ask for;
- **the view builders,** which turn what the engines answer into what a screen shows;
- **the art assembly** for screens: busts, figures, backdrops;
- **dev mode's panels:** in-game, the same engines, more permissions;
- **the app shell** (desktop/).

**What it doesn't own:**

- **sentences:** those are Story's;
- **world building and saving:** those are Core's;
- **game rules:** those belong to the engine they're about.

## Verdict

The split between the browser and the server is clean:

- the client imports no engine, apart from the written-number helpers in english/plain-words.mjs;
- screens read engines' tables but never write them;
- dev mode's writes go through each engine's own writer;
- nothing in the game imports the screens.

The problems:

- **dev mode isn't in the installed game;**
- **the view builders read engines' tables and keep a few rules;**
- **five word files live in the screens;**
- **the play server and the client are each one giant file;**
- **about 4,000 lines of checks and tools sit in the game folder.**

- An engine's live session builds its own doors.

## The finished product

```
engines (people, elections, laws, budgets...)       Story (all words)
   │ each answers through its door                       │ lines, names, terms
   ▼                                                     ▼
the reader (core): history + a row by id ──► view builders (screens, server side)
                                                │ one route file per screen
                                                ▼
                                    play server route table (handler.ts)
                                                │ the same in the bench and the installed app;
                                                │ dev routes behind the in-game permission
                                                ▼
                                    client: play.mjs + one ui module per screen
                                                │
                                    app shell (desktop/): window, updater, host
```

- **A screen never opens an engine's table and never words a sentence.** It asks the engine's door for live things and the reader for the past, and it shows Story's words.
- **Dev mode** is the same screens with more permissions, in the installed game.
- **For a modder:** a new screen is a view builder, a route file and a ui module, with nothing to edit inside an engine.
