# Agreement 1-4: Lane 1 (run and govern) and Lane 4 (the game screen)

Owner: Lane 4. Lane 1 wrote these first entries on Nov 3 because no Lane 4 session was running. Lane 4 confirms each one or amends it here, and the second lane to merge brings its code in line (ruling 5).

## What each side reads and writes

- **Lane 1 writes the answer; Lane 4 shows it.** Who may file for which race, and from which day to which day, is decided in one place: `playerMayFileFor` and `filingWindowOpen` in `src/core2/modules/elections.ts`. Lane 4's screens (the clerk's counter, Campaigns, `src/bench/government.ts`) read that answer and never compute their own.
- **Lane 1 may make one-line edits in `src/bench` to switch a screen from its own computation to the engine's answer.** Example: in #7085, `government.ts`'s `filingOpen` reads `filingWindowOpen`. Each such edit is named in the PR body under "Review: Lane 4", and Lane 4 may rework it later.
- **Tests in `src/bench` that file the player through the engine** (`one-council-race.test.ts`, `filing-counter-petition.test.ts`, `filing-intro.test.ts`) find their race through the clerk's list (`playerContests`), the same answer the screen shows. When Lane 1 changes the filing rule, Lane 1 updates these tests in the same PR, and does it the same way. Each update is named in the PR body. Lane 4 owns everything else in `src/bench`.
- **Controls Lane 4 adds** (buttons, panels) call the engine's acts and never write campaign or filing records themselves.

## The check

The filing and office browser checks pass: New Game, then the clerk's counter, offers one race of each body while its filing is open, and filing there shows the race on Campaigns.
