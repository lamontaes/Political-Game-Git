## Procedure

1. Inspect the actual populated screens and current approved artwork. A blank
   design mockup is not evidence a busy government/person view will fit.
2. Compare two coherent skins on the SAME representative content/layout rather
   than inventing two menu architectures. Define shared type, spacing, surfaces,
   border/icon/control sizes and focus/hover/selected/disabled/error states.
3. Keep the scene visually dominant; make useful objects and people discoverable
   through restrained highlights, hover AND keyboard focus. Deliberate click or
   keyboard activation opens the relevant context. Hover/reading never commits
   an action, spends time, grants knowledge or changes a saved relationship.
4. Preserve real person/object/record binding, focus return, Escape and the
   shared clock. Do not inject repeated generic day buttons into feature panels.
5. Fit primary panes at the actual embedded viewport and a narrower supported
   size. Keep text legible and controls reachable. QAR1-06 is resolved: dedicated
   long-document/history/directory readers may scroll with search/sections;
   main decision panes have no nested scrolling. Preserve alphabetical hometown
   browsing. Never use
   overflow:hidden or microscopic text to declare the problem solved.
6. Preserve the withdrawn status of the Politics default/tab-dragging proposal.
   Keep approved layouts, art identity and intro direction unless specifically
   changed. A new skin is not a data model, fictional document system or engine.
7. Use real data for production, explicitly labeled fixtures for isolated
   prototypes, and runtime text for changing names/dates/headlines. New generated
   pixels need the owner's normal art approval; no fake review events.

## Completion evidence

For design: return same-layout comparisons, token definitions, state examples
and a recommendation. For authorized implementation: trace the selected tokens
through real shared components; exercise pointer/keyboard, resize, long content,
focus return, reduced motion and normal Save/Continue. State exactly which
proofs ran and which did not. Screenshots alone do not verify interaction or
persistence. List discovered, fixed and remaining bugs in the final report.
