# Play first: the bench and browser checks

Part of the `play-first` skill. Traps with the bench, browser checks, claims and stacked pull requests, from the lane's passes.

## Bench, browser checks and claims

- **Restarting the bench.** TypeScript and bank files load once, so restart `npm run bench` after a change to `src/bench/*.ts`, `src/core2` or `data/english`. Find it with `ps -eo pid,args | awk '/[b]ench\/server.ts/ {print $1}'` and `kill` those pids; `pkill -f` or `pgrep -f` with the path in the command kills your own shell. Start it with `setsid nohup npm run bench > log 2>&1 &`. The browser check needs `BENCH_BROWSER=/opt/pw-browsers/chromium-1243/chrome-linux64/chrome` in the cloud (the repo's Playwright expects another build).
- **After an out-of-memory kill, restart the bench and stop only your own (Nov 12, Fixer F2).** A browser check that fails at once with `waitForResponse: Target page, context or browser has been closed` and a `dmesg` line `Killed process ... (node)` means the kernel killed the bench or Chromium for memory on a shared machine; the bench process stays listed but no longer answers (`curl -m 5 localhost:<port>/api/title` prints `000`). Do not `pkill -f bench/server.ts`: it can kill other sessions' benches and the permission check refuses it. Find your own bench with `pgrep -f bench/server.ts`, kill only the pids whose `/proc/<pid>/environ` holds your `BENCH_PORT`, start it again with `BENCH_PORT=<port> nohup npm run bench > <log> 2>&1 &`, wait until `/api/title` answers 200, and run one check at a time with `; echo EXIT=$?` after it (a pipe to `head` or `tail` hides the exit code).
- **A menu that does not fit gets fit by measure, not a counted formula** (Nov 1, #6973: row counts worked out from the window height failed in the next drawn place when a long office title or a big body took more room). `src/bench/menus-fixed.browser.mjs` opens every menu and Politics tab at 1440 by 900 and 1280 by 720 and names the element that runs past the bottom; the fix is `pager.setRows` or `fitToPanel` in `play.mjs`, which tighten after the screen is on the page. Run it on five fresh draws before sending a menu change to its checker.
- **Sweeping a work order's unclaimed items** (Nov 1, Codex package D): list the lane's `status: open` items, check for a `codex/` or other branch that holds each (`git branch -r | grep <slug>`), claim the free ones one at a time with `claim`, and for each first reproduce it on a restarted bench. About half were already fixed on main: a fix with its test already merged, or a check that already covers the case.
- **Close a stale item with evidence, not a rebuild** (Nov 1: `golden-draft-list-names`, `play-stop-12-status-card-covers-menu-after-canvass`, `tests-filing-browser-go-times-out-on-main`). Run the item's own check on the restarted bench in drawn places (name each place and seed), append a dated Notes line saying what already fixed it (commit or PR) and the run, and send that change in the hour's pool bundle (`pool-notes`; owner, Nov 11: a pool-only change is not a pull request of its own).
- **A claim that did not take is not a claim.** If `claim` prints done but the item file on main still reads open with no `claimed-by` (an item that already carries a `pr:`), the item is not yours; do not build on it, and tell the CTO.
- **Browser checks rewrite tracked screenshots.** Some checks save into `docs/` paths git tracks (`docs/reports/...` including `docs/reports/people-web-2026-10-14/web.png`, which `people.browser.mjs` rewrites, and `docs/play-first/shots/sitting-oct28/`); run `git status` after a check and `git restore` those files before committing, unless the PR is about them.
- **A browser check starts a life through `src/bench/start-life.mjs`** (Nov 3, Lane 5): `startLife(page, { url, fresh })` for the title screen and new world, `playOpening(page, sceneMomentId)` after a check's own new-life click (the address opens about 400 ms after the card, so it waits for the staged talk first), `toReplies(page)` to Continue a talk to its replies. They press Continue and the first reply, never Skip scene. A check that reads the opening itself (opening-address, opening-montage, talk-box, rates-named, room-talkable-after-story) plays it its own way; wiring the helper into one of those takes the talk it reads. Checks also drop `calendar-*.png` in the repository root: delete them before committing.
- **A check that times out at the start of a life is usually the opening still playing, not the screen under test.** A check that makes its life through the creator waits for the `/api/newlife` reply and calls `playOpening(page, sceneMomentId)` before it looks for the card or the rail; the card is hidden while a scene plays (Nov 11: `continue-face` and `faces-at-open` had both stalled on main this way; the rail is hidden while a scene plays, so `faces-at-open` now starts through `startLife` too). A check whose screen is gone is deleted, with what it tested and why it cannot pass in the PR body, never patched to pass (Nov 11: `people-center-face` tested the People web, which the list-beside-card People screen replaced).
- **Which files a restarted bench reloads.** `play.mjs`, `play.css`, `play.html` and the `ui/*.mjs` parts are served from disk on every request; TypeScript, `controls.json` and the data files load once at start, so restart the bench after changing them (a missing control label shows up as `Cannot read properties of undefined (reading 'replace')` on the page). Kill it with `ps -eo pid,args | awk '/bench\/server|npm run bench/ && !/awk/ {print $1}' | xargs -r kill`: `pkill -f <name>` also matches your own shell's command line and ends your tool call (Nov 1).
- **A check that opens a menu must first live through what the last act left.** An act can leave a scene's talk or a stop on screen, and pressing a menu's ring while that menu is already open closes it. Settle the talk and stop first (`#talk-leave`, `#talk-next`, `#continue`), and return at once if the card you want is already open (`campaign-trail.mjs`, Nov 1: four of six fresh draws failed until it did).
- **Assert the cause, not an outcome the data may also produce.** Same-sex couples are in the place's own data, so "the partner is the other gender" fails on a real draw; the cause (a woman drawn with a husband and then written over) is "the drawn resident's gender equals the chosen one" (#7074, Nov 1). A check on fresh draws names the cause, and a send-back on one draw is answered with five.
- **A campaign act becomes a scene with one pattern** (Nov 2, donors #7109, volunteers #7111, endorsements #7112): the act's answers each carry `name` and `line` (`standingLine` with a bank move), the result carries `scene: askScene(core, personId, <place row in scene-places.json>)`, and play.mjs plays it through `playAsks` (one Continue per person, then the summary). Add the bank pieces, the place row and a browser check that asserts each Continue's name and text equal the API's, on two drawn places. Put a `Touches:` line 1 until the last button is gone, and update `SG-PLAY-campaign-acts-buttons`.
- **Bank pieces about a person avoid pronouns and "anyone"** (Words on #7112): no "their" for someone whose record gives a gender, and no absolute the record can contradict ("will not endorse anyone"). Words adds trait-varied spoken versions later; ours stay for summaries.
- **A new check that opens the trail uses `openCampaignTrail`** (`src/bench/campaign-trail.mjs`): it settles any talk or stop first and returns if the trail card is already open; never click the Travel ring blind.
- **A stacked PR carries the base's head.** When PR B builds on PR A (the same lines of one file), merge A's head into B each time A changes and tell B's checker; the PR number mod 5 sets the checker for each, so two stacked PRs can have different checkers (#7083 and #7087, Nov 1).
- **A check can open the bench without a life.** After `/api/newlife`, a life with nothing yet (an adult from the Advanced start) can have an empty Journal; a screen that indexes the first record must handle none (Nov 1, the Journal crashed on no chapters and the sheet never opened).
- **A browser check or test that files a candidate follows the clerk.** Filing is a petition and refuses a resident of another town: pick a person whose `placeId` is the town's (`lawChain(api).townPlaceId`) and accept a filing that is `petitioning` or `on-ballot` (Oct 29, `donor-calls.test.ts`).
- **When main refuses your handoff push** (required status checks), comment the lines on your PR and message the CTO; do not retry or edit `.git`. Never run a status flip with `--by=cto` yourself: only the CTO, or a second session's `pool seen` check (`seen-in-game`), sets an item done.
- **Messages.** Since Oct 29 sessions whose work meets message each other (`docs/coordination/CREW.md`); ask the owner of a file before you build in their area, and tell them which functions you change.
