# Civic gameplay audit

Read the repository authority order and the exact applicable feature contract.
Start with the parent's named journey, source SHA and acceptance question, not
an inventory of every feature. A fixture proving a writer is not an ordinary
player entry; a footer or count is not a compiled/native delivery proof.

Trace entry → player choice → authorized canonical writer → actual time/resources
and other actors → recorded consequence/information → save/reopen → return flow.
Inspection spends no game time unless an existing disclosed action requests
work. Preferences are not consent for legal or irreversible decisions; missing
or private information is not character knowledge.

Use fast source reads first. If ordinary-route execution is authorized, use the
existing source-identified browser runner and a disposable test profile. Test
semantic controls with pointer and keyboard activation, not only DOM presence.
Never touch real saves, replace an installed app, kill other owners' runners or
weaken a failing test. Keep private screenshots/payloads local.

Report demonstrated findings with exact head, file/symbol, minimal reproduction,
expected/actual, severity and current owner. State which checks actually ran and
which remain NOT RUN. Use qualitative uncertainty, not political rankings,
success odds or generic ability scores.

## Stop condition

Acknowledge the parent's follow-up once and return a concrete result; no
recursive audit/status chain.
