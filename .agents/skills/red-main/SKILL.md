# Red main

Red main comes first (owner, Oct 15; `AGENTS.md` "How every session works", step 2). One red, one branch, one ready PR whose line 1 is `Touches pool item: release-main-red-standing`. A fix to a red check is a check or tooling change, so it merges ahead of other pull requests (owner, Nov 10: rules, checks and skills merge first; `merger` section 0b). Put the red's test, place and seed and your progress on that PR, where the next agent on any tool finds it. Fix at the root; never skip, disable, quarantine or allowlist a test, and never widen a bound without saying why in the PR body.

## 1. Read the verdicts first

Read the newest run of Release, Deterministic validation, M0 guards and Every place nightly on main (the Actions runs for branch main; with the GitHub tools, `actions_list`, or `gh api repos/lamontaes/Political-Game-Git/actions/runs?branch=main`). A push run on main is canceled by the next push, so the scheduled runs are the verdicts. A report that is "red on main" may already be green: check the newest run before building (Oct 29: two reds on the list were fixed by earlier merges).

## 2. Name the red by test, place and seed

A red is not named until you have the failing test, the drawn place, the seed and the exact assertion. A failure that flips by seed is a defect (one rule, all 56 places): find the seed-dependent branch, not a lucky seed. Pass the seed with `GOLDEN_PATH_SEED=<seed>` (and `GOLDEN_PATH_PLACE_KEY` where the test reads it). A test's printed seed may be the place seed, not the run seed (mark-gap prints `place.seed`): reproduce from it directly (`buildBenchWorld(<place seed>, ...)` or `/api/build?seed=<place seed>`), because passing it as `GOLDEN_PATH_SEED` draws another place and passes (Oct 29, Port Vincent, Louisiana). Not every test reads `GOLDEN_PATH_SEED`: grep the file for `process.env` first (`campaign-door-balance.test.ts` reads `DOOR_SEED`, `door-fill-in` `DOOR_FILL_SEED`, `dev-outlook` `DEV_MODE_SEED`, `daily-register` `DAILY_REGISTER_SEED`). A seed passed under the wrong name is ignored, and the run draws a random place that it never names as a replay (Nov 13, the Red desk's door-balance runs on #8976). Golden-path specs run through `src/bench/m0-check.ts` or `npx vitest run <files>`; the command is in `docs/roadmap/features.json`.

## 3. Find the owner, then message before touching

`docs/coordination/CREW.md` lists the running sessions and their areas. A red in an engine a running session owns goes to that session with the test, place and seed before you touch it; after an hour of silence it is yours. Elections, history, offices and the nightly have no running owner. Questions for the owner go to the CTO.

## 4. Reproduce, then go to the cause

- Reproduce on clean main first. If it does not reproduce, say so with the seeds you tried; do not fix a guess.
- Clean main means main's head fetched just now, not the commit the red was reported on. Before fixing, search merged PRs and the engine owner's channel block for the test's name: the owner may already have fixed it. On Nov 1 a fix for `scene.test.ts` at birth-n1 and bb-fresh was built on the test from before Words' merged fix (#6989), so merging it would have undone that fix (#7027, closed).
- Run world tests one process at a time. Eleven long vitest files in one call killed two workers (`Worker exited unexpectedly`, memory) and left those two without a verdict; run each long file alone, with a timeout longer than 30 minutes for the director's full-year tests (`circumstance.test.ts` outran 28 minutes), and say "no verdict" for one that times out rather than "passes".
- `pkill -f <pattern>` can kill your own shell when the pattern is in your command line; wait for a run to end with `until ! pgrep -f "runne[r]"` instead.
- Use `NODE_OPTIONS=--max-old-space-size=8192` for world runs; `tsc` over the whole project may run out of heap, so typecheck by running the changed tests.
- Stack of a thrown error: `vitest run` output cut to the lines starting with `❯`. When two writers collide on one key, record the stack of each scheduling in a temporary Map and print the first when the second arrives; remove it before the commit (Oct 29, `Duplicate institutional calendar key`: two review chains for one couple).
- Call the failing step directly before reading the engine: in the empty-talk red (Oct 30) the greeting worded fine when called alone, which pointed past the wording to the owner's rule that clears a talk with nothing on record.
- When a test's premise changed with a ruling (the six-offices rule moved the player's first race to the next even year), fix the premise and quote the ruling; when the ruling exposed a gap the test is right about (no beat for a year after an early filing), leave it red and message the owner of the gap.
- A test red on one seed, with two values a hair apart, often reads one side after the act and the other before it. Find which value each side reads, and when. On Nov 1 `campaigns.test.ts` recomputed a volunteer's shift share after the walk, when a retelling had already warmed them. The engine had weighed them before the walk, so the test was wrong and the tolerance stayed at 9 decimals.
- A test that expects every record to become a scene must allow for the director's own reasons for keeping one off the stage: the season cap (`seasonCap`) and an evening's sitting that took the ask in. It names the reason, takes the next case, and still fails on an unexplained miss (Nov 1, `ask-before-the-roll.test.ts` in Springfield, Oregon).
- Bisect with the failing test as the oracle when the cause is not in the stack: `git bisect` on the known good and bad merge commits, one run per step.
  - On a train or any branch built from fold merges, bisect only the folds: `git bisect start --first-parent <bad> <the fold that brought the test in>`, then `git bisect run` a script that runs the one test alone and exits 0 when it passes, 1 when its own failure message is printed, and 125 on anything else (a build error, a timeout), so an unrelated break is skipped, not blamed. Forty folds took six runs of about a minute and a half (Astoria OR, Nov 15, first red fold c01ae17c). Then ask the fold's builder whether its change or the test's premise moved before filing the item.
  - The bisect script imports only what both ends hold. A support file that came with the test (`tests/support/real-borrower.ts`) is missing on the older side, so every step exits 125 and the bisect blames nothing; copy the few helpers the oracle needs into the script's own file. `git bisect reset` returns to the commit the bisect started from, not to main: check the branch before the next run (Nov 17, a probe after the reset read the green side).
  - A pinned case can move with the world. When the pinned borrower stopped missing payments, the cause was a fold that moved a housemate's first paycheck by a month, not a credit fault. Show the case's own records on main (the payment rows, paid in full), name the fold by bisect, and hand the test to its owner. Waiting longer is a raised budget (CTO, Nov 17, 03:12Z: the test moves to drawn places).
- A fix that fails somewhere new has found the next assumption, not a reason to stop: read what the new failure assumes. If three assumptions in a row each need an exception (Oct 29: a dead parent as a person broke household, place, tier and opening-income checks), the design is wrong; step back to the tier that never reaches those loops (a husk).
- Read the assertion before the report. A message quoting "748 people, 0 beds" was the passing print of another test in the same file (Nov 1, housing): the real failure was a fixture that failed every time. First ask whether the red is by draw or fixed: a fixed-seed fixture that fails every time means a rule or data under it changed (since Oct 28 a world's shelter rate is the published rate times a per-seed offset), so size the fixture from the rate the world reads.
- A decision that looks wrong may be the engine's own rule. Read the recorded position's terms before calling it a fault (Nov 1, committee markup: a member who traded for a section voted no because `consistency` was -1 from three questions they had just voted the other way on). Fix the test's premise and quote the rule, or ask the owner for a design change; do not bend the engine to a test's guess.
- A test that needs a rare premise (a worker who loses a counted job, a place with a shelter bed, a household with someone left at home) must draw among places where the premise holds, or redraw and say why (words-engine, test-pick lesson). Check how many drawn places hold it before touching an engine. In the speech red (Nov 1) the first sixty adults filled whole households, so nobody was left at home to retell it: the engine was right.
- Prove a suspect merge is not the cause by running the same seed on main before it and after it (Merger 1 cleared #6935 this way, Nov 1). If both fail the same way, the cause is older: do not send it to the suspect's author.
- Read what the nightly's check reads, not only the symptom. The Seats check reads each seat's roster, so a refill that seats the new holder on a fresh seat leaves the dead one's seat empty (PR #6972 needed a second push for this). `all-places --world-seeds <s>` draws its own place; to reproduce the nightly's places use `--only <states> --seed <the run's seed>`.
- Before changing an engine for a calibration red, measure the candidate over every state's data and over a sweep of draws, on main and on the branch (mean and largest error against the source); ship only if the mean does not get worse. Centering turnout on the voter's own state fixed Mississippi and broke a Minnesota draw (Nov 1): the same fix was wrong alone and right beside the state-habit term it needed.
- A roster check must read how the engine seats a holder. The nightly's Seats check read only the officials roster, but a special-election winner is a serving term with no person until their seat is first read (`holderOf`), so held seats were reported empty (Austin, Arkansas, Nov 1). Dump the seat's vacancy, official and term rows from the check itself before touching an engine; a check can be the defect.
- A test that picks a case by a state and checks it days later must read that state again on the day (Nov 1, renewal: the household could pay the trip when picked, 30 days in, and had no cash when the pregnancy ended three months later, so the engine rightly paid 0; the plan's recorded `cashMinor` says so). Skip such a draw as the test skips "none ended".
- A test for a mechanism that moved is a stale test, not a red: find the commit that removed the mechanism (`git log -S` on its id), and delete the test when the successor's own test already holds the guarantee (opening-kin's `:move:` facts became `person.moved-in` records in `past-moves.ts`, tested there). Replace, never layer.
- A throw that names a missing record (`Closure requires an actual current unfunded obligation receipt`): list every writer of the thing that names the record and every reader that must accept it. Three writers set `unfundedBusinessReceipts`; `closeEmployer` accepted a cause from only some of their kinds, and the legacy calendar-average pay result (kept per person) was missing. Fixing one path often reveals the next (the same Superior run then failed on a rehire), so ship the first and file the second.

- **Check main's head before fixing, and again before the PR.** Three of the first seven reds on Nov 1 were already fixed by a merge that landed while the fixer worked (#6989 for `scene.test.ts`, #7028 and a later main rule for `legislature-committees`). Fetch `origin/main`, rerun the pinned place and seed on that head first, and rerun `git log origin/main -- <test file>` before opening the PR; a duplicate is closed with a one-line comment naming the merged fix.
- **A rare premise is a test fix; prove the rate.** When a test redraws places until the world "shows" something (a filled-in worker losing a counted job, a lease open on the last day, a household that borrowed), draw eight places and count how many show it before touching the test. Nov 1: 2 of 8 showed a filled-in counted job loss, so three draws missed it four times in ten. Then stage the rare thing through the game's own path in the drawn place; never turn its assertion into an informational line, and add a pinned witness place only with a CTO line on that pull request (`done-proof`). Keep every assertion that a thing which does happen is right (every job loss answered once, every open lease has a living payer).
- **A test that follows one tier misses the other.** A counted household is a `group` row and its loans may use another ref (`loan:small-dollar:<id>:`); a check that follows only full households' rows and plain refs reads "nobody borrowed" (`law-wiring-housing`, Nov 1). Follow both tiers.
- **A test that calls an engine's rule must pass what the engine passes.** `medianTransactionBalance(pay)` without the world seed gave one number for every world (`press-staff-cash`, Nov 1: the same 948308 in every place). Read the engine's call before writing the expected value.
- **A nightly's premise can misread early endings.** The every-place Ballot check counted any term ending between Nov 1 and Mar 1 as a scheduled election, so a term cut short by a vacancy ("accepted incompatible office") showed as a missing contest. Read the term's `endedBy` and the `vacancies` table before calling the ballot engine wrong. Do not state a cause you only inferred from a count (I said three top offices were vacated from a seat count and had to correct the PR).

## 5. Ship

- Run the failing test before and after on the named place and seed, plus two fresh seeds, and the other tests of the changed module. For a change to the opening population run the golden-path suite (`node --import tsx tests/golden-path/runner.mjs`, about 20 minutes, in the background) and tell a runner timeout from a failed assertion.
- Add a release declaration in `docs/release/changes/` (`impact: none` needs a one-line reason body) and run `release:check --mode pr`, prettier, and `pool --check` for any pool item you add.
- PR body: the red as reported, the place and seed, the cause, before and after, what the fix does not cover, and the owner you told. A stale assertion is fixed in the test only when the code's rule is a recorded ruling; quote it.
- `npm run pool -- add` commits and pushes the item to main itself, so a branch has no file to commit afterward; check `git ls-tree origin/main docs/pool/items/` before looking for it. `--area` must be one of laws, gov, elections, office, world, core, people, director, words, play, art, release or docs. Run `npm run pool -- --check` before `add`, because `add` pushes to main and cannot be retried quietly: its `--rules` line must name the standing rules as AGENTS.md spells them (for example "No dice", "One model, two tiers"), each with a reason (the CTO fixed a failing item on Nov 2).
- When a fix uncovers a different failure behind the first, ship the first, and file the second as a pool item with its numbers (search `docs/pool/items` for a twin first) or message its owner.
- A before number from main's files: put them in the tree and restore your branch's in the same command (`cp`/`git checkout origin/main -- <files>; run; git checkout HEAD -- <files>`), never commit in between, and run `git status` after. A probe copy of a test goes in `.git/info/exclude` and is deleted before the commit; build its injected lines with a script, not a heredoc with newlines inside a JavaScript string (a split string killed a 5-minute probe).
- A type import across folders is a guard failure waiting: run `tests/guards/families.test.ts` (seconds) before pushing, and import through the other family's entry file with a re-export there (PR #7044 imported `./work-cash` into finance and turned main red; #7056 fixed it). Never raise `families-baseline.json`.
- A verdict run with `timeout N` that expires prints "Terminated" and gives no verdict: run it in the background and wait with an `until ! pgrep -f "runne[r]"` monitor (see `speed-work` (heavy-runs part)). Never `git worktree add` a full checkout (2.2 GB, helper-checkout); edit skill and docs files on a branch of the main checkout when no run is using it.
- **Out of memory at the default heap is a trace, not a heap bump.** CI runs node's default (about 2.2 GB; check `v8.getHeapStatistics().heap_size_limit` after `unset NODE_OPTIONS`). Run the file with `env -u NODE_OPTIONS` at the seed to reproduce, then find what grows: log `heapUsed` after `gc()` (`NODE_OPTIONS=--expose-gc`) after the build and every 90 days, and print `moduleTableSizes(core)` at day 0 and day 600 (`src/core2/module-state.ts`). `law-wiring-housing` at `hr-fresh-9c2` showed 1.3 GB after the build (about 570 MB the world, the rest imports) and 2.0 GB after 700 days, from campaign door, cause and pledge rows. A population ceiling in the test left no town to play. The fix belongs to the table's owner (the fold items in the pool), not to the heap. A town's size does not predict it: a 48,000-person town ran the same file at the default heap.
- **Never `pkill -f vitest` in the same shell.** It killed the session's shell (exit 144) on Nov 2. Wait for a run with `until [ -f <name>.done ]` and stop one with the PID it printed.

- **The hourly full run (CTO, Nov 8: reds were found by accident, because a PR's checks run only the test files it changes).** About once an hour, at the first break between other pieces of work after an hour has passed (never a sleep loop or a timer), in your own checkout at the newest `origin/main`: run the full unit suite and `npm run guards`, one process, alone (`speed-work` (heavy-runs part)). For each red post one line on #8928 that starts "Dev Tester: red on main", naming the test, the commit that broke it (bisect to it) and the owning session, and message the coordinator the same line so it reaches the owner and the owner's fix goes to the front of the desk's line. Name the main commit of each run in your PR bodies.

A red from the words machine (`npm run words:rules`, `tests/guards/english`) names a line or a rule. A rule a program can judge pulls the failing line (`data/english/pulled.json`); the rewrite is the Story session's, so a red-main fixer lists the line and does not edit `data/english/parts/` (owner, Nov 10, "Split by role"). A red in a rule is fixed in the rule's test, not by weakening the rule.

## 6. Keep the record

Every two hours write a block at the top of `## Red main` in `docs/coordination/LEADS-2026-10-24.md` (commit to main: `leads: red main status <time>`): each red, its cause, its PR, main's newest verdicts. A probe that fails is checked for a timing artifact before it becomes a bug (Oct 29: a check read the clerk's status before the clerk's morning run).

## Lessons of Nov 17 (the Red main lane's first five reds)

- **Bisect a pinned test back to the fold that brought it in, and run the pin's own branch head.** The promise tests' pinned borrower (Ragland, Alabama) was green on its pull request's head and red on the very fold that merged it, so it had never been green on the train or main. Before looking for "the change that broke it", run the oracle on the pull request's head and on its fold: if the fold is already red, the pin held only in its own branch's world and no later change is to blame.
- **A cloud clone is shallow; deepen it before a bisect.** `git fetch --deepen=400 origin main` brought the train's folds in a minute. `git bisect start --first-parent <bad> <good>` then needs the script to exit 125 on anything that is not the oracle's own verdict line.
- **A red that names one spec may be every spec's.** M1-11 threw at a place with no household to play in, but the fault was the runner's drawn key, which about 45 files build by. Count the callers before fixing one, and fix the one place they share.
- **Read the failing job's own message before trusting a pool item's cause.** The item for `press-comment-variants` said "no call by draw"; the red on the pull request was a different assertion at a different seed, and both were real. Take the seed from the job log, replay it on clean main, and only then read the item.
- **A browser check that waits for the page to settle counts the page's requests; it does not use Playwright's network-idle state.** That state stays reached once it has been reached, so `waitForLoadState("networkidle")` returns at once later on. Attach `request`, `requestfinished` and `requestfailed` listeners before the press whose answer you wait for: a listener attached after the press misses the request already on its way (`watchRequests` in `src/bench/start-life.mjs`).
- **Log the page before you theorize about a browser red.** An init script that records each change of two elements with its time showed the opening's talk closing, the room showing for 719 ms and the next talk opening. Two fixes written before that log did nothing.
- **`npm run pool -- claim` and `status` push to main.** On an account whose rule is that nothing pushes to main (`pool-notes` (file-a-pool-item part)), edit the item on your branch instead.
- **Post the cause before you build, even when the build is the probe.** Twice the fix was found by trying it; the cause line still goes on the crew's thread first, with "found by trying" said plainly.

## Gotchas (Nov 16 and 17)

One line each: what happened, its cause, and what to do. From the crew threads (#9747, #9750) and the CTO's log.

- Nov 17, 02:18Z (golden-path M3-09): the last spec timed out on pull requests that never touched it. Cause: the specs shared one quick-budget clock, so the earlier ones starved it. Give each spec its own measured clock (#9832); never raise the total or skip the spec.
- Nov 17, 20:30Z (#9881, #9915): six reds on a pull request's unit run were mostly the train's. Replay each at CI's seed (the test's own variable, `GOLDEN_PATH_SEED` or `DEV_MODE_SEED`) on the train's head before calling it yours. A red on a pull request that changes only tests is the train's engine.
- Nov 17, 20:50Z (dev-discharge, #9881): a probe that called `chairHears` before the vote turned a held bill into a heard one. Cause: the early read changed what the committee decided later, so the probe measured a different world. Print a decision's reasons from the record it wrote, after the step runs, never by calling the reader early.
- Nov 16, 23:52Z: five lanes chased the same `guards` red. Cause: it came from a skill on main. Read one failing log before sending lanes to look, then name the commit on main that fixes it.
- Nov 18, 04:10Z (`answered-question-not-offered`, #10086): a test threw "A job ends before its day's work" on a train that changed no jobs code. Cause: `hire()` ended the old job without `workedToday(c, person)` as `afterShift`, which `leaveWork` already passed. Read the stack's first engine frame (`npx vitest run <file>`), then look for the sibling call that already guards the case; fix the caller, never the test's day.
- Nov 18, 03:20Z (#10045, #10066): `guards` red on a pull request against the train was the base's (a spelling flag and a `check-changes` crash, both fixed on the train later). Read the failing line first, then bring the train in with the update-branch call (never merge main into a branch already folded), and post the new head once its checks finish.
