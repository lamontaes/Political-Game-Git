# World-bound gameplay composition

Read the current owning brief and `AUDIT-RETURN-2` and retained `AUDIT-RETURN-1` in the Decision Register before treating old audit examples as requirements. Use the existing World, clock, identity/history and source consumers. No subagents, recursive helpers or new coordination platform. Model/effort follows the actual authorized application, not this file. A skill describes procedure; it grants neither a new game rule nor permissions. Distinguish source inspection, isolated tests, actual played behavior, merge and installed delivery.

## Required input

Identify the exact source/head, current writer, owning feature, approved product
meaning and relevant open QAR1 choices. Read only the existing consumer and writer
paths the change touches. Existing starting points include
`src/simulation/legislation-content-contracts.ts`,
`legislation-program-families.ts`, `legislation-drafting.ts`,
`life-opportunities.ts`, `people-study-plan.ts`, `decisions.ts`,
`src/presentation/contextual-scene-producers.ts` and their actual current callers.
Locate renamed paths normally; do not recreate a second engine when a name moved.

## Procedure

1. Identify the fixed instance and the useful reusable semantics underneath it.
   Separate an isolated test fixture from an ordinary-world production default.
2. Describe components and compatibility constraints. For policy: objective,
   instrument, subject/target, eligibility, duties, payer/funding, enforcement,
   exceptions, start/end and amendment/repeal. Reuse the existing contract's
   supported fields; propose an extension only when real gameplay needs it.
3. Bind to the saved jurisdiction, relevant people/institutions, present needs,
   existing law and actual resources. A cosmetic title or seed-only ID hash is
   not a causal context. Do not invent a missing real-world fact as evidence.
4. For encounters, bind participants, their own information, a plausible reason
   to act, optional choices, independent responses and actual later consequences.
   Ordinary activity may be produced by the shared clock without a prior menu
   click. Rendering/hovering itself never manufactures the premise it reads.
5. Distinguish what the player proposes from what was adopted, paid, done and
   observed. Different observers can learn different things from one occurrence;
   observation must not repeat payment or implementation.
6. Before a consequential new formula/range/restriction becomes normal play,
   submit its compact researched module proposal and contrasting generated
   examples through the existing owner review route. Mark unapproved values as
   proposals. Do not ask the owner to choose helper names or equivalent code.
7. Implement the approved grammar and actual effects through existing writers.
   Generate readable text from the same structured meaning. Missing optional
   research should not block an approved simulation rule; a missing effect
   consumer remains unfinished, not a claim of implemented results.

## Completion proof

Demonstrate different worlds changing meaningful terms/choices/consequences,
not merely names. Preserve same seed/version reproducibility; relevant state
changes should change eligible composition. Check incompatible combinations,
no-action/authority/funds/knowledge cases, duplicate commands, persistence and
one actual ordinary entry/decision/follow-up route. Do not preselect only a seed
that hides an error. Required coverage follows the brief, not a sample ceiling.
Return the changed behavior and fixed/open/deferred bugs to the coordinator.

## Stop only the dependent part

An unresolved new product meaning, unavailable required input or overlapping
writer holds its particular change. Continue approved independent work. Do not
reintroduce an exact-charter gate, fixed universally named statute, mandatory
homework or scripted outcome merely because an old test assumed it.
