# Effects link audit

Explain how a named cause reaches a named result and whether the implemented amount has evidence. Pin the source head and link ID. Follow the actual consumer before classifying a null or missing catalog size: a separate person-level producer may exist.

## Audit each link

- Identify cause, result, producer, canonical record, consumer and affected cohort. Run the current feature-walkthrough why-chain to recorded circumstances, research, a stand-in, a draw or a missing mechanism.
- Record size, unit, denominator, range/evidence spread, response shape, lag and duration. Cite source population, period and causal/descriptive limits. Distinguish percentage points from percentages and per-person effects from town totals. Missing research remains explicit; a source citation alone does not validate a coefficient.
- Trace both increasing and decreasing causes. Check thresholds, floors, ceilings, saturation, reversibility and delayed effects against evidence. Do not assume symmetry or permit impossible totals merely because the equation is signed.
- Trace the per-world draw and its stable key, range, persistence and consumers. Verify one saved value is reused appropriately rather than redrawn on every turn. Legal values remain exact where law requires them; variable effects use their researched range. An arbitrary seeded probability does not supply a person's reason for acting.
- Identify person-level opportunities, resources, decisions, exposure and recorded outcomes. Reconcile people and money with aggregate totals without double counting overlapping links. Explain every reaction or documented inert outcome. Absence of a producer is not evidence that nobody noticed.
- Work one numeric example from actual records where available. State all inputs, units, calculation, lag, resulting records and aggregate reconciliation. If only an illustration is possible, label it explicitly and source every assumption; never describe it as observed gameplay.
- Check plausible low/high worlds and historically supported extremes. Name evidence bounds, impossible states and unanswered cases. Do not tune to a target result without evidence or call a clamp research.

## Hand-back: one row and one example per link

Row fields: link ID; cause/result; source head; producer/consumer; population; size/unit/denominator; range and source; shape; lag/duration; increasing/decreasing behavior; bounds; per-world key/save behavior; person mechanism; wired status; research gaps; owner and smallest repair.

Below the row provide the worked example with numbers and provenance, an extreme-case check, why-chain terminal, and executed proof (command, head, result and limits). Mark NOT RUN where appropriate. Summarize added/changed links separately from newly proven runtime chains. Source checks, watched results and owner approval remain distinct.

Keep fixes within current claims and existing systems. Put missing features on the owner's list. Use the current scoped-test and approval route; this skill does not authorize new teams, merges or guessed research.
